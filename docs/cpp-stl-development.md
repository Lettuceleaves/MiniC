# C++ STL 兼容开发记录

目标是在算法题范围内保持 C++ 的源码使用习惯，包括 `vector<int>`、成员调用、迭代器、比较器、常用算法和自动资源管理。容器存储和算法实现放在自研 `lib/cpp/*.mh` 中；编译器负责通用语法、对象生命周期、静态实例化及代码生成。外部 G++ 只作为测试参考，产品编译链不依赖它。

本记录对应 `codex/cpp-stl` 分支，基于 `5e26b38` 创建。工作树带入的 UI 改动不属于这组提交。参考材料是用户提供的《STL手册》，其中过时 API 单独列为兼容扩展，具体语义以 C++17 为目标。

## 当前状态

用户在已有功能与 O01–O13 验收之后提出继续针对性优化，并明确新的性能门槛：**当前 Windows x64 上，MiniC `OPTIMIZED` 对 G++ 系统 STL，11 个主负载与 4 个批量模式每一项进程耗时均不超过 1.2 倍**。此门槛仍在推进中，不能用平均值、部分项目改善或既有功能验收代替。保持相同源码、输入、完整输出校验和测量范围；每轮冻结产品、保存样本，并优先消除实际瓶颈。工作继续保留在 `codex/cpp-stl`，不合入、不推送。

新增门槛的[第一轮诊断结果与原始样本](../benchmarks/iterations/2026-10-02-round1/README.md)固定在 `7a1f731`：405 次执行全部通过输出校验，含 270 个测量样本；15 项仍全部高于 1.2 倍。deque 本轮为 5.936 倍，相比前一独立批次的 16.126 倍明显改善。此轮有 13 个测量样本短于 100 ms，不作为最终性能门槛验收。

[第二轮诊断结果与原始样本](../benchmarks/iterations/2026-10-02-round2/README.md)固定在 `eda431e`：合并后的目标回归 556/556 通过，405 次原生执行全部匹配原始 oracle。混合位集计数为系统 STL 的 1.094 倍、稀疏位集计数为 0.882 倍；其余 13 项仍未达到门槛。二分查找 1.890 倍、有序映射 1.728 倍、deque 3.993 倍、字符串 2.855 倍、短字符串 3.042 倍，批量模式为 1.329–1.639 倍。此轮其他组有 20 个测量样本短于 100 ms，仍是诊断记录；最终验收须在后续固定版本完整满足每项门槛。不同轮次比率是分批测量，不当作同时配对的旧新速度比。

第二轮纳入单前驱控制流合并、私有局部地址归一化、只读形参提升、内联后标量准备、循环内联优先级和寄存器成本估算、比较与逻辑非分支融合、聚合标量写入宽度修复，以及字符串字节批量操作。每片有独立 RED/GREEN 证据；下一轮继续针对临时复制、常量实参内联、字段地址读取和字符串数据访问，不以已有两项达标代替全部完成。

2026-10-02 后续第一轮已提交：`81f7bb9` 将 deque 头插分配槽检查从重复扫描改为仅新增块（计数探针 15,360 → ≤30，21 项目标及相关验收）；`71ab464` 实现有符号/无符号常量二次幂除法与余数和立即数移位编码（175 项独立验收）；`d07ec46` 直接化已知函数地址调用（11 项验收）；`b76865f` 按被调用函数优先顺序准备有预算的内联候选并删除已证明非零的整数检查（251 项相关验收）；`88f071e` 接入原生优化流水线（三项组合 RED → 421/421 GREEN）；`7a1f731` 修复带尾随立即数的 RIP 相对移位重定位（三项 RED → 10 项 GREEN）。各组测试有交集，不将其相加冒充完整回归数量；这些结果尚不证明达到 1.2 倍。

```java
CompilerApi compiler = new CompilerApi(
    sourceFile,
    LanguageMode.CPP17_ALGORITHM,
```

O12（`9ca3169`）把 15 个字符及末尾零保存在 `string` 对象内；Windows x64 对象仍为 32 字节，使用空堆指针选择内联存储，不保存指向自身的指针。短串构造、移动、交换和短别名编辑的自研库堆分配计数为零；不同对象之间的整串复制在容量足够时不分配，否则只分配一次。原库短串场景 155 次分配和长串复制多一次快照分配均有实际 RED，改后 14 项目标、16 项相关回归全绿，覆盖 BASELINE/OPTIMIZED native、checked debug、G++ 系统库和 G++ 自研库。日志与冻结清单在 `build/string-sso-implementation/`；这些是语义和分配计数验收，不是耗时结论。

O11 库路径（`8f88b58`）只把已存活、相同整数类型、非 volatile 对象之间的赋值转成 `memmove`。vector 复制赋值的公共存活前缀和 erase 的左移复用此路径；构造新对象仍逐元素执行。copy/move/copy_backward/move_backward 保留原公开模板签名，由内部 helper 分派连续指针；类、代理、转换赋值和 volatile 仍走原循环。公开函数取址与显式模板参数的 8 项实际 RED 修复后全绿，连同目标和相关回归共 55 项唯一验收全绿，见 `build/o11-live-integral/`。debug 批量复制传播逐字节初始化状态，因此未初始化错误可能延后到目标被读取时报告；未读取的复制不作为 G++ 未定义行为差分。旧 G++ 8.1 对一个平凡可复制类的模板赋值选择有已复现偏差，该精确版本仅用独立显式赋值循环作语义对照，原始系统库输出仍保留。

O13（`19d1188`）在字循环内部使用无符号 SWAR64，同时保留零／单置位的快速路径和 `MINIC_BITSET_FORCE_KERNIGHAN` 后备宏；`all()` 直接检查完整字及末尾掩码。两个原生模式的 count/all 汇编均无 helper 调用。独立逐位模型覆盖 0、1、63、64、65、127、128、129、1024 位及移位、翻转、末尾位，默认／后备分别经过四后端验证。存储字数改用先除后加余数，避免 `N+63` 溢出；超出当前数组布局上限的类型继续明确诊断，不能悄悄成为单字对象。最终 12 项验收全绿，见 `build/o13-bitset/safe-final.txt`；这里不要求参考 G++ 拒绝 ISO 允许但超过 MiniC 布局上限的类型。

`1d46402` 修复原有 string 原始指针迭代器与零整数下标的重载歧义。迭代器位置模板按可隐式转换的类型参与决议，并各转换一次；混合 iterator/const_iterator、不可复制转换对象及合法零下标均保留。12 项接口和 14 项 SSO 复验共 26/26 通过，原始 `replace(0,0,s.data(),0)` 无需 cast，见 `build/string-iterator-overloads/`。`b9a5091` 增加独立的批量操作成对基准，4 项工具测试和两个固定产品版本的 8 个构建 × 4 个模式全部通过输出校验，该阶段未正式测时；随后四模式共 256 个正式样本纳入最终报告。基准记录复制与观察元素数，完整哈希、初始化和 erase 后重建均包含在进程耗时内。

### F03 的提交与验收边界

F03a 已完成，保存类语法和源码身份。`StructDecl` 增加可选 C++ 元数据，旧构造器及布局使用的 `fields()` 保持兼容；元数据按源码顺序保存字段、方法与访问标签。`class` 默认 private，`struct` 默认 public；`this` 使用独立表达式节点。先按声明点解析成员签名，再在类成员登记完成后解析内联方法体，使方法体能看到后声明成员。方法体使用原 token 的有界区间，错误恢复不得吞掉后面的成员或顶层声明。F03a 的历史提交只接受语法，后续由 F03b 接通执行；各阶段均不得丢弃未实现的语义后继续生成代码。验收包括 AST 不可变性、字段投影的对象身份、函数指针字段与方法区分、源码范围、声明点与完整类语境、错误恢复和 C 回归。

### 原生初始化诊断的边界

原有 native 初始化标志仅由直接局部存储更新，无法看到指针、引用、被调用函数或 CRT 的写入。`int x; fill(&x); return x;` 因此曾在有效赋值后仍返回 101。当前原生后端只对函数内未取址的局部变量承诺这项附加诊断；对取址局部不发出失真的标志检查，也不在取址时伪造一次初始化。分类基于实际发射的 IR，DCE 可继续将无用取址视为纯运算。源码 IR 和调试器不变，debug 仍按字节追踪别名、部分写入与循环声明重置；读取未初始化对象本身是 C/C++ 未定义行为，不能拿 G++ 的此类输出当正确性 oracle。

该边界以避免误拒绝有效源码和避免增加原生影子内存开销为目的，不宣称 native 与 debug 对所有未定义行为提供相同诊断。C/CPP 的直接、跨函数、条件、转发、多层指针、`sscanf` 和循环赋值先得到 14 项真实失败、6 项已有正确行为，修复后 20/20 通过；未取址读取在 BASELINE 和 DCE 模式仍返回 101，取址后的未初始化读取由 debug 报错。证据在 `build/native-alias/`。

这些子步骤依据 C++17 的[类成员完整性规则](https://timsong-cpp.github.io/cppwp/n4659/class.mem)、[成员函数规则](https://timsong-cpp.github.io/cppwp/n4659/class.mfct)、[`this` 规则](https://timsong-cpp.github.io/cppwp/n4659/class.this)、[成员访问规则](https://timsong-cpp.github.io/cppwp/n4659/class.access)及[调用求值规则](https://timsong-cpp.github.io/cppwp/n4659/expr.call)。仅解析、已经执行和仍待实现的能力分别记录，不应相互替代。
