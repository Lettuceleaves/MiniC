# UIAPI / UIWeb Refactor Report

## Summary

本轮改造把 MiniC 的网页端能力收束到 UIAPI 契约之上：`uilocal` 不再保留组合后端流程和派生 UI 语义，`uiweb` 通过 HTTP UIAPI adapter 对齐本地能力，并补强了网络失败、异步状态、debug/realtime 降级和验证闭环。

## Implemented Work

- UIAPI 新增 `runToExecution()`、`stageViews()`、`inspectorModel()` facade，并通过 HTTP 暴露：
  - `POST /api/observation/{sessionId}/run-to-execution`
  - `GET /api/observation/{sessionId}/stage-views`
  - `GET /api/observation/{sessionId}/inspector`
- `UiStageViewDto`、`UiInspectorModelDto` 下放 stage card 与 inspector 的派生语义。
- `UiGlobalDataDto` 新增 `executionInputPending` / `executionInputConfirmed`，并兼容旧 Java 构造器和旧 JSON payload。
- `uilocal` 改为消费 UIAPI facade/DTO，移除本层 `runToExecution` 循环、stdin magic string 判断、stage/inspector 派生逻辑。
- `uiweb` 补齐新增 DTO、HTTP adapter、ViewModel state、error/pending 状态和 adapter completeness 校验。
- 修复网页端 start pipeline、editor render、diagnostics、debugger、bottom tokenize、realtime failure、debug failure 等断点。
- 补强 UIWeb verification：runtime workflow、failure resilience、snapshot parity、screenshot parity、console warning fail-fast。
- 修复 JavaFX/theme 与 UIWeb CSS placeholder warning，补齐 visual binary/red-black tree samples。

## Review Fixes

- HTTP control route 改为惰性执行，先校验 method/path 再调用有副作用的 API。
- `refreshDebug()` 局部视图失败不再被成功路径清空错误状态。
- `refreshAll()` 先提交 core state/stage/global，再独立获取派生 UI DTO。
- HTTP client 对非 JSON 4xx/500 body 保留 status/method/path。
- verification scripts 在启动失败时清理 UIAPI/Vite/browser 进程。
- snapshot parity 覆盖新增派生 DTO 和 `UiGlobalDataDto` 新字段。

## Verification

- `.\gradlew.bat test --warning-mode all`
- `npm run verify:strict-final`
- Targeted Java/UIAPI tests and UIWeb checks were also run during development.
- Three subagent review rounds completed; final A3/B2/C2 review reported no findings.

## Notes

- Existing user-local changes remain present and were not reverted: `config/settings.json`, `tmp/path-scan/`.
- `uiweb-render-check/` is generated by screenshot verification and should remain untracked.
