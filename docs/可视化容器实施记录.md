## C27 AST 树契约、IDE 卡片样式与 Pipeline 性能修复（并入 C26 未提交批次）

## C28 大规模源码的 Pipeline 性能修复（并入 C26/C27 未提交批次）

用户用包含 10 个 STL 头的程序复现“性能非常糟糕”。探针先量化了根因：Pipeline 模式对每个编译步都捕获并全量重建投影，词法阶段 77898 步每一步都拷贝累计 token 列表并重建整页，模型侧每个 AddNode/Compose 又整页拷贝并全量扫描组合，形成多处 O(n²)。

| 修复 | 内容 |
| --- | --- |
| 整阶段批处理 | `PipelineSession.nextStage` 在阶段循环内关闭逐步 Context 捕获，只在终态捕获观察并投影；中间帧按历史协议本就会被丢弃。失败终态仍进入 pending，重试不消费编译步骤；`nextStep` 保持逐帧实时 |
| 批次草稿事务 | `MutationTransaction` 由每命令整页拷贝改为批次粒度草稿：被触及页面首次复制后原地更新节点、组合、拓扑与就绪集合，终态物化一次并做全局校验；父槽位与规范化端口对边使用索引判重 |
| 投影重放 | `ProjectionContainer` 为已有组合建立 (parent,child,slot) 集合，输入侧重放不再对每条组合扫描整页 |

### C38 画布空白（看起来卡死）：长字段行撑破布局单元（并入未提交批次）

用户报告跨断点后仍然"卡死"。现场取证：窗口消息可响应（`IsHungAppWindow=false`）、所有线程池空闲（5 秒 CPU 增量 0.03 s）、强制 GC 后存活 199 MB——不是死循环。真正的症状是**画布一直空白**：复现多变量捕获（`nums/numSet/words/freq/freqVec/uniqueWords`）时 FX 线程抛
`IllegalArgumentException: Text obstacle outside unit: Rect[x=48, width=314.8] vs Rect[width=185.6]`。

根因：连续槽容器（`ARRAY` + `POINT` 子节点）在 `layoutSlots` 里只用槽内容重算卡片宽度，忽略了同一张卡上的字段行（例如 `type=std::map<std::string, int, std::less<std::string>>`）。字段文本比卡片宽 → `LayoutRequest.Unit` 的障碍校验失败 → `renderFrame` 在 FX 线程抛异常，页面永远画不出来；每次布局重试都再抛一次，表现为"卡死"。`std::vector<int>` 这类短类型行不会触发，所以之前只有部分变量看起来正常。

修法：`layoutSlots` 计算帧宽时取 `max(槽内容宽, 本卡字段行宽)`，卡片宽度取 `max(ownWidth, boxX + boxWidth + PADDING)`，字段行与槽列表同宽不越界。

TDD：新增 `VisualizationRendererFxTest.contiguousSlotArraysWidenTheirCardForLongFieldRows`（长 map 类型行 + 两个槽），首轮真实 Red（`Text obstacle outside unit: 314.8 vs 185.6`），修复后渲染器 16/16、`UnitObstacleProbe` 对 39 页 258 个节点 0 失败。真实 UI 流程复跑：开始 442 ms、两段跨断点 559/452 ms、到结束 55 ms，最多 50 页 304 节点全部渲染成功、`pending=false`。门禁 runId **`20261006-160244-822621fb`**：基线 868 项（687 通过、181 按平台条件跳过、0 失败）、模型 130、布局 52、适配 183、FX 49、原 UI 回归 10 全绿。
