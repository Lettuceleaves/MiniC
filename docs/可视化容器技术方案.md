日期：2026-10-05

状态：C00—C29 已实施并通过累计验收，包含 C24、C25 深度审计补正与 C26–C29 的 Pipeline 工作台及性能修复；C30 为待验收的调试工作台（右侧栏与右侧信息栏），C32 增加调试器连续桶数组布局（`BUCKETS`）与 IDE 卡片样式。逐提交证据见[实施记录](可视化容器实施记录.md)

C26 完成右侧 Pipeline 工作台；C27 修正 AST 的树契约与 Pipeline 性能（AST 投影只保留首次发现的父边，树页不再因共享引用降级到 Graphviz，Pipeline 卡片改用 IDE 暗色样式）。

C28 修正大规模源码的 Pipeline 性能：整阶段批处理只捕获和投影终态，模型事务按批次 copy-on-write，消除投影重放与模型提交中的 O(n²) 扫描；C29 将编译各阶段（词法、语法、语义、IR）压到 O(n)，并修复序列显示上限、卡片批量挂载与文本度量缓存。

适用项目：Craken，设计时源码基线为 `6a44875`

本方案把已经确认的可视化容器模型落实为纯 Java 状态模型、JavaFX 展示组件、Pipeline 适配器和 Debugger 适配器，并规定实现顺序、测试判据及每次提交前的验收门禁。文中的类、任务和脚本按实施记录逐项交付；第 18 节保存方案制作时的基线事实。

需求依据是本次讨论的最终确认。与旧文档冲突的概念以本文为准：取消固定层及层 ID；节点归属图无环，页图允许环；导航从聚焦节点选择上游；同一页可在一帧内重复出现；页内没有主结构，使用 part 表达连通分量。布局算法与配色继续遵循[图算法选型](图可视化算法选型.md)和[配色规范](Craken-可视化组件配色设计规范-v1.md)，页宽函数沿用[布局方案](可视化布局方案.md)。

文中“需求约束”表示已确认的行为；“实现约定”表示本方案为消除接口歧义而选定的实现方式。后者可在实现前评审，但不能改变需求约束。

## 1 目标与实施范围

实现一个可独立使用的可视化容器。调用者注册页类型、创建节点、提交关系和内容变化，容器维护身份、归属、part、焦点与展示路径，并将完整的已提交状态交给绘制层。

首版范围如下：

- 容器内唯一页 ID、页内唯一节点 ID，使用递增 `long`，不复用。
- 页初始化时必须注册类型；支持页类型和 ViewNode 子类扩展。
- 一页允许零至一层语义嵌套，支持数组内部的子 ViewNode。
- 多种双向关系分别管理，支持页内有向及无向绘制连线。
- part 拆合、就绪缓冲状态、节点归属 DAG、共享引用及级联释放。
- 聚焦页与节点、上游选择 index、向上高亮、自动导航开关。
- 同一个 Page 模型在当前路径中出现多次，每次有独立展示实例。
- 纯 Java 快照、事务更新、后台布局、JavaFX 场景更新与资源关闭。
- Pipeline 双容器、AST 两组位置、各阶段投影及既有终态回看。
- Debugger 手动结构注册、VM 事件适配及历史展示恢复。
- 每个实现 commit 的编译、累计 TDD、回归、报告核验与暂存检查。

就绪列表的可滚动 UI 按用户要求后做。首版必须完成其模型、转移规则和测试，不以缺少列表控件为理由省略状态。特殊数据结构自动识别器保留扩展接口，首版使用调用者显式注册。三维渲染、任意两层以上页内嵌套、另一套全局类型监控框架均不进入首版。

## 3 模型与不变量

### 3.1 身份与注册

`ContainerModel` 持有 `HashMap<Long, PageModel>`。每个 PageModel 持有 `HashMap<Long, ViewNode>`，包含已分配的就绪节点、part 节点及数组内部节点。不存在 Layer、Layer ID 或按层存页的注册表。

公共位置使用纯 Java 值类型：

```java
public record PageRef(long containerId, long pageId) {}
public record ViewLocation(long containerId, long pageId, long nodeId) {}
public record OperationPath(ViewLocation pre, ViewLocation nxt) {}
```

`pre` 是本次操作选定的归属上游；`nxt` 是目标节点。ROOT 保留节点的 pre 为 null；根页中的 OWNED 节点仍须携带有效上游，不能按所在页判断。两端必须属于同一容器；在确定容器上下文内可使用 pageId/nodeId 简写，但跨模块和快照使用完整位置。VM 地址、AST 对象身份和展示 ID 分别管理。

实现约定：

- ID 从 1 开始，0 不表示有效对象；空位置使用 null 或 Optional。
- 容器 ID 在进程内不复用；页 ID 在容器生命周期内不复用；节点 ID 在页身份生命周期内不复用。
- 失败事务已预留的 ID 留下空洞，不能返还；历史恢复不倒退分配器高水位。
- HashMap 只提供查找。数组槽序、part 顺序、父引用顺序分别保存。
- 相同业务对象是否复用既有 ViewLocation 由调用侧身份映射决定，容器不使用内容相等判断对象相同。
- 页类型在初始化时确定并冻结。需要换类型时创建新页并显式迁移，而不在旧页中静默换解释规则。

### 3.2 五种关系

“双向绑定”统一表示两端有可查询的索引，但必须记录关系类别。

| 关系 | 方向与用途 | part 连通性 | 归属引用计数 | 上行导航 |
| --- | --- | --- | --- | --- |
| TopologyEdge | 同页绘制边，方向仅决定箭头 | 按无向邻接参与 | 不参与 | 不参与 |
| CompositionLink | 同页数组等展示包含关系；每个子节点只有一个包含父节点 | 作为虚拟连接使一个展示单元归属同一 part | 不参与跨页计数 | 不参与 |
| OwnershipBinding | 上游节点指向下游节点的归属边 | 不参与 | 参与 | 参与 |
| PartMembership | part 与成员的派生登记 | 不作为新的边 | 不参与 | 不参与 |
| PageBindingRule | 节点级或整页级初始化规则，生成实际 OwnershipBinding | 不参与 | 规则本身不计数 | 通过生成的节点边参与 |

TopologyEdge 可以成环；CompositionLink 必须同页、无包含环；OwnershipBinding 只表达跨页归属，必须保持节点 DAG。不能把反向查询索引作为相反方向的归属边。

页图允许环。例如 `A.a1 → B.b1 → A.a2` 合法；再建立 `A.a2 → B.b1` 会形成节点环，必须拒绝。实现不对页图做无环或引用计数假设。

### 3.3 语义嵌套

约束的是数据结构展开的语义深度，不是 Java 对象树深度或 ViewNode 子类数量。

| 展示包含 | 语义嵌套深度 |
| --- | --- |
| array → primitive cell | 0 |
| outer array → row array → primitive cell | 1 |
| outer array → middle array → inner array → primitive cell | 2，只有声明 ≥2 的页类型接受（默认不设上限） |
| 链表 next 连线、树内连线、字段展示包装 | 不因此增加嵌套 |

PageType 声明嵌套接口 `PageType.SemanticNestingPolicy`，对包含转换给出 0 或 1 的语义增量；累计不得超过页类型自己声明的 `maximumNesting`。该值不设默认上限，只要求非负：内置类型通常声明 0 或 1，二维数组、拉链哈希声明 1，三维及以上数组的调用方按需声明更深的值（例如调试工作台把声明为 `int[3][3][3]` 的被捕获变量展开成三层）。接口定义在 PageType.java 中，只负责判定一次包含转换的语义增量。展示用标题、字段行、端口包装不增加语义深度。容器验证调用者提交的展示组合，不推断 VM 类型或 Java 泛型。

### 3.4 根保留与存活

根页是容器的唯一根入口。以 pre=null 在根页创建的节点具有 ROOT 保留方式，允许归属入度为 0，只有显式删除或容器关闭才释放。以有效 pre 创建的节点具有 OWNED 保留方式，事务提交后至少有一个有效上游绑定，包括就绪节点和嵌入数组的内部节点。根页也可以收纳 OWNED 投影节点；其身份不因所在页是根页而自动变成 ROOT。

页内绘制连线不保活节点。数组包含对子展示节点有组合生命周期约束：删除数组 ViewNode 会删除其内部展示子节点，再按通常规则清除这些子节点的归属与绘制关系。它不通过增加跨页引用计数实现。

这两种规则作用于展示对象。Debugger 或 Pipeline 负责判断真实业务对象是否应发送删除事件，容器不代替源语言的内存管理。

### 3.5 提交后必须满足的不变量

1. 每个存活节点恰好登记在一个页中；每个页 ID 恰好登记在一个容器中。
2. 所有关系端点均存在，正反索引一致。
3. OwnershipBinding 的有效父节点集合与引用计数一致，归属节点图无环。
4. 每个 OWNED 节点至少有一个上游；ROOT 节点不接收跨页归属入边。
5. 父引用选择 index 指向有效数组元素；无父引用的根节点使用 -1。
6. 组合包含无环，子节点最多有一个包含父节点，语义嵌套不超过页声明能力。
7. 就绪集合与 part 成员集合不重叠；每个已进入展示的节点恰好属于一个 part。
8. part 与节点登记一致，part 等于展示图的弱连通分量。
9. 焦点为空或定位存活节点，聚焦页等于该节点所属页。
10. 导航按有序节点链生成，不对 pageId 去重。
11. 一次成功事务只增加一次版本、发布一次已提交变更；失败事务不发布状态。

## 4 模块与依赖方向

```text
Pipeline 编译上下文                 Debugger VM 中立事件
         ↓                                  ↓
craken.visualization.adapter.pipeline   craken.debug.visualization
         └──────────────┬───────────────────┘
                        ↓
            craken.visualization.api
                        ↓
        纯 Java 模型、事务、导航、快照
                        ↓ 不可变描述
          布局引擎与 JavaFX 展示组件
```

核心模型、公共位置和命令协议不依赖 JavaFX、CompilerApi、DebugRuntime。布局输入输出也不依赖 JavaFX；文字和控件测量由 FX 层完成后传入尺寸。VM 事件接口不依赖 ViewNode 或任何绘制类型。两套适配器共享可视化更新协议，不共享对象识别或运行流程。

容器对外门面是 `VisualizationSession`。JavaFX 控件 `UiVisualizationContainer` 负责显示该会话，不能同时承担 VM 监控、AST 遍历、连通分量计算和布局算法。

## 7 API 与错误协议

### 7.1 公开入口

以下为公开接口的主要入口，便捷重载见 VisualizationSession：

```java
interface VisualizationSession extends AutoCloseable {
    PageRef initializeRoot(PageType type);
    PageRef initializePage(PageType type, PageBindingRule.Spec binding);
    ViewLocation reserveNodeId(PageRef page);
    MutationResult modify(MutationBatch batch);
    VisualizationSnapshot snapshot();
    void restore(VisualizationSnapshot snapshot);
    @Override void close();
}
```

新节点还没有 ID，不能要求调用者先找到它。采用 ID 预留：调用者取得尚未登记的 nxt 位置，然后以 `AddNode(pre, nxt, spec)` 提交；事务失败时该 ID 仍不复用。同一批次可以引用先前预留的新位置。位置预留不产生可见节点或分配事件。

初始化子页可以注册节点锚点或大页规则。页初始化的空状态允许存在，节点提交必须满足实际上游绑定约束。根页只能初始化一次，页初始化也走校验与版本管理。

### 7.2 命令语义

| 命令 | 行为 |
| --- | --- |
| AddNode(pre,nxt,spec) | 若 nxt 是有效预留位置则创建；若已存在则只增加归属绑定，不重建内容、状态或 ID |
| AttachOwnership(pre,nxt) | 增加归属，选中 pre；重复同一来源的绑定幂等 |
| DetachOwnership(pre,nxt,source) | 删除指定归属来源；有效父关系消失时修复选择，最后归属消失时参与级联 |
| Connect(pathA,pathB,direction[,aPort,bPort,style]) | 创建同页具体端口间的 TopologyEdge，激活对应就绪展示单元并合并 part；简写使用 node 端口及默认样式 |
| Disconnect(pathA,pathB) | 删除绘制边，重算该页分量，不删除拓扑邻居 |
| SetContent(path,content) | 修改目标展示值；必要时重测量 |
| Touch(path,accessKind) | 查询或访问目标，产生高亮，返回读取内容 |
| DeleteNode(path) | 全局删除 nxt，清除所有入向、出向及其他登记；pre 只确定操作路径 |
| Compose(parent,child,slot) | 注册同页包含，验证语义嵌套；混合就绪状态时整单元进入展示，不把已展示节点降回 READY |
| BindPage / UnbindPage | 新增或撤销页级动态规则及其生成的归属来源 |
| SetFocus(path) | 明确用户导航位置，允许根节点 pre=null |
| ClearFocus() | 管理性清空焦点和访问高亮，保留活节点和开关；用于无存活上游的释放事件回退 |
| SetPageLayout(page,hints) | 更新显示根与部分展示顺序，不改变焦点和访问高亮；删除节点自动裁剪提示 |

TopologyEdge 与 OwnershipBinding 必须使用不同命令，不能靠“有没有箭头”推断是哪一种边。Connect 的两个端点分别携带 OperationPath；两端的上游可能不同。管理性的 snapshot/位置查找不等同于业务 Touch，不自动产生导航。

AddNode 和 AttachOwnership 可以建立新的上游关系，验证候选端点、保留方式、页类型及最终节点 DAG，不要求候选 pre 已在父数组中。SetContent、Touch、DeleteNode 和现有端点的 Connect/Disconnect 则要求 OWNED 目标的 pre 是当前有效上游，ROOT 目标使用 pre=null。全局删除仍需合法操作路径；删除其他父关系是其明确语义，不只删除此次 pre 对应的边。

### 7.3 返回错误

模型更新使用 `VisualizationError(code,message,commandIndex)`。实际错误分组如下；错误消息补充具体位置或规则，避免让调用者依赖消息文本区分类别。

| 实际代码 | 对应校验 |
| --- | --- |
| UNKNOWN_POSITION / UNRESERVED_POSITION | 外来容器、未知页/节点、无效预留身份 |
| PAGE_TYPE_MISMATCH / NESTING_LIMIT | 不支持的节点种类、扩展工厂或复制契约、语义深度 |
| INVALID_OWNERSHIP / OWNERSHIP_CYCLE | 无效 pre、ROOT/OWNED 约束、归属环 |
| COMPOSITION_CONFLICT | 包含环、重复父节点或槽位 |
| INVALID_COMMAND / SESSION_CLOSED | 无效命令、绑定来源、端口/布局提示或已关闭会话 |

布局异步失败使用独立 `LayoutException.Code`：INVALID_TOPOLOGY、RUNTIME_UNAVAILABLE、TIMEOUT、PROCESS_FAILED、INVALID_RESULT、CANCELLED。类型初始化和位置预留返回直接值，缺少类型、重复根初始化或 long 分配空间耗尽会抛明确异常；不伪造一个成功 ID。这里将设计初稿的细分错误名称映射到已发布 API 的分组，不改变整批失败和布局错误隔离语义。

业务校验失败返回错误及零起始命令序号，整批不提交；最终图校验失败归属于批次最后一条命令，不返回越界序号。程序员违反线程或内部不变量可以抛异常，不能吞掉后继续发布。ID 到达 long 上限时明确拒绝分配，不溢出或复用。

## 8 原子更新与生命周期

### 8.1 一批更新的顺序

1. 在唯一模型写入线程读取提交版本，保存原焦点选中的完整上游路径，作为间接级联释放的回退依据。
2. 建立受影响页与关系的草稿，记录新预留 ID。首版使用受影响区域的 copy-on-write，未触及页共享不可变已提交值。
3. 验证命令输入，应用显式内容、拓扑、组合和归属变化，展开本批新增节点所需的动态绑定。处理 DeleteNode 时先按其 pre 更新目标选择，再在清除关系前保存目标的完整回退路径。
4. 标记显式删除对象，并先禁止动态规则重新绑定这些对象。
5. 在最终显式归属状态上计算组合删除及 orphan 级联，清理所有关系与登记。
6. 对受影响页计算最终 part，修复父引用数组、index 和页规则。
7. 根据操作与选项确定新焦点；释放时选择删除前路径上最近仍存活的上游。
8. 验证全部最终不变量，包括归属节点 DAG、嵌套、父引用和已修复焦点的合法性。
9. 原子替换已提交状态，版本加一，发布一次 ModelChangeSet 与不可变快照。

事务不在中途渲染，监听器不能观察到半边关系、临时 orphan 或中间 part。添加所有候选归属后，对最终候选图进行迭代 DFS 或 Kahn 校验。单条新增边也可先从 nxt 搜索 pre，提前发现错误；只按当前导航链检测不够。

已提交的内容、槽位顺序和关系集合只读。第一次写入时复制对应节点及集合；关系变化必须复制两端，级联新触及的页加入草稿。PageType 提供内容复制与快照转换协议，不能保留调用者仍可修改的集合、AST 或 VM 对象。失败事务不得通过共享可变内容污染已提交模型或旧快照。

同一批 `解绑旧父 → 绑定新父` 不得在解绑瞬间级联释放。全局 DeleteNode 则优先于本批重新 Attach：对删除集合中的目标重新绑定返回错误，调用者需用新 ID 表达新对象。

### 8.2 part 和就绪状态

就绪是显式状态，不能按节点当前度数推断。未开启就绪时，新独立展示单元立即生成单节点 part；包含子节点加入其数组单元的 part。开启时保留最初示例中的空页例外：页尚无存活节点时分配的第一个展示单元直接进入 part，后续独立单元进入 READY；包含子节点跟随所属单元状态。空页判断包含就绪节点，不能因当前没有 part 就把已有 READY 节点当成不存在。同批首次分配按命令顺序确定首个单元。

首次有效页内 Connect 将涉及的 READY 单元及内部节点共同移入展示状态。两个 READY 单元相连也生成 part。归属绑定与 part 登记不触发这次转换。Compose 两侧均为 READY 时保持 READY，两侧均已展示时合并相应 part；一侧已展示、一侧 READY 时，将整个组合单元提升为已展示。这个规则适用于 READY 数组包含已展示子节点及已展示数组接纳 READY 子节点两种方向，任何节点都不降回 READY。进入 part 后断链，即使变成孤立节点也保留单节点 part，不返回 READY。

PartPlanner 在受影响页上构建展示连接：TopologyEdge 忽略方向，CompositionLink 作为内部虚拟邻接。排除 READY 集合后，用迭代 BFS 求分量。初版复杂度为该页 `O(V+E+C)`，C 为包含关系数。并查集可优化连接合并，但不能单独解决断链拆分。

实现约定使用分量最小节点 ID 作为内部 part 排列键，纵向排列。它不是公开长期身份，拆合后可以变化。渲染位置复用通过存活节点匹配，而不依赖 part 键永不改变。

### 8.3 归属计数和级联释放

归属按有效的上游节点关系计数。同一对 pre/nxt 可有显式绑定和页规则生成的多个来源，来源分别登记，但只形成一个有效父数组条目。只有全部来源撤销后，才减去这个父关系。重复同一来源的 Add 幂等。

全局删除 nxt 时清除它的全部父关系及下游关系，不受当前引用数保护。共享保护用于其下游：解除一条归属后仍有其他上游的节点保留，最后一个上游消失才加入释放队列。

释放使用迭代队列和已删除集合，不能使用与导航深度等长的 Java 调用递归。每个被删节点清理：归属、绘制边、包含、就绪、part、焦点关联和页规则来源。删除拓扑邻居间的边不会自动删除那些邻居。

Page 不使用页图引用计数。非根页没有存活节点且没有有效初始化保留规则时移出容器注册表；共享节点仍存活时页必须保留。空且仍有有效锚点的页可保留为空页供再次懒加载。根页保留到容器关闭，最后一个根节点删除后允许空焦点。

### 8.4 动态节点页和大页

节点锚点规则为子页新节点绑定指定上游节点；大页规则为父页与子页所有节点生成实际归属关系，包含双方的就绪节点。实现上将整页规则展开成实际节点关系，不能把页反查当成父引用。

新增父节点或子节点时，只展开增量组合；新增关系仍需节点 DAG 校验。两个页互为大页且会形成节点环时，拒绝整个注册或新增批次；普通节点级路径造成页环则允许。

规则生成的关系携带 ruleId 来源。UnbindPage 撤销该规则全部来源；DetachOwnership 只撤销指定显式来源，不能把仍由规则提供的父关系当成已删除。调用者要撤销整页生成关系，使用 UnbindPage。DeleteNode 强制删除全部来源并把目标从规则作用集合中移除。

规则只响应初始化、显式新分配、父节点增删和规则变更，不作为“发现孤儿后给它寻找新父”的修复器。当前删除集合中的节点不能被复活。一个有 P 个父节点、Q 个子节点的大页规则最多产生 P×Q 个关系；首版明确承担该成本，测试覆盖增量与清理，后续可在保持语义的前提下压缩索引。

### 8.5 焦点和选择修复

每个 OWNED 节点持有 insertion-order 的父数组及 selectedParentIndex。操作通过 pre 找到其条目，更新 index；删除数组前面的元素时同步减 index，不能让它跳到另一个父节点。

所选父关系被移除且仍有其他父关系时，从原位置顺延至下一个有效条目，末尾回绕；删除非选中条目时维持原选中身份。最后父关系失效的 OWNED 节点进入级联释放。

DetachOwnership 是归属关系管理命令，只移除指定来源，不先把即将删除的关系选为访问路径；否则删除非选中关系也会错误跳转到第三个父节点。真正的节点访问、内容修改和显式 DeleteNode 仍按 OperationPath.pre 选择路径。

焦点节点释放前已经保存选择链。释放完成后跳过本批同时释放的上游，选择最近存活者；不存在时聚焦节点为空，根页仍可显示空状态。不得在删完全部入边后再尝试通过已失效 index 找父节点。

显式删除先按调用者 pre 选择父引用，再保存回退链。autoNavigate=true 时删除操作以目标 nxt 的这条链确定新焦点，即使 nxt 原来不是聚焦节点；autoNavigate=false 时保留原焦点，只在原焦点被此次显式或级联删除时修复。间接释放使用删除前已保存的焦点链，不能临时为 orphan 选择一个已断开的父关系。

## 9 导航与展示实例

### 9.1 按节点生成路径

NavigationResolver 从 focus.node 开始，读取该节点 parents[index]，将准确的父节点作为下一次起点，直至遇到 ROOT 节点的空上游。不能只走 Page 的一个父指针，也不能一遇到 rootPageId 就停止；根页可能在节点路径中重复出现。

每个节点步骤生成一个 PageOccurrence，其身份至少包含当前导航节点位置。最终反转为根到焦点的顺序：

```text
归属节点路径：R.r → A.a1 → B.b1 → A.a2
展示出现顺序：R(r), A(a1), B(b1), A(a2)
共享页模型：A
独立展示实例：A(a1) 和 A(a2)
```

节点 DAG 保证这条选择路径有限。实现仍使用 visited 节点位置检测内部状态损坏，不能按页去重。使用循环而不是 Java 调用递归，支持很深的合法路径。

焦点为空且根页已初始化时，生成一个空根页出现位置；容器尚未初始化或已关闭时返回空帧。

### 9.2 自动定位与高亮

autoNavigate 和 propagateHighlight 默认均为 true，分别可关闭。业务增删改查按需求更新目标的父选择 index；autoNavigate 控制是否把焦点改为本次目标。删除则始终修复已经失效的焦点，不能因开关关闭而保留悬空位置。

实现约定：关闭 autoNavigate 不冻结真实归属或 index。若当前焦点的某个祖先选择因操作改变，当前路径仍按最新 index 重算。开关的含义是“不主动聚焦另一个目标”，不是保存一条已经不符合模型的路径。

向上高亮沿本次选择的上游链传播，不展开全部共享分支。默认随目标切换导航时，每个出现位置应用自己的导航节点高亮；ViewNode 子类可扩展为高亮内部槽位或关联展示节点。大页虽然提供多个有效上游，当前路径仍高亮选中的那个上游节点。关闭向上传播时仅目标实例应用节点自身规则。

当自动导航关闭，访问同一个已显示页中的其他节点仍须高亮，但不改变焦点。存在重复页时先匹配精确导航节点，否则选择上游路径公共前缀最长的同页出现位置；并列时按路径深度就近，距离相同则靠近焦点。不把高亮广播给该页的所有副本。焦点尚为空但根页已显示时，根页节点也可接受访问高亮。目标页未出现时只记录访问状态，不强行插入另一个页面；就绪目标同样保留高亮状态，后续就绪列表控件可显示它。

### 9.3 页宽与视口

沿用 q=2、间距 g=8px、最小可见页宽 b=160px。n 是路径出现次数，不是唯一页数量；A 出现两次占据两个位置。优先显示最靠近焦点的 m 个出现位置：

```text
净宽 A = W - (m - 1) * g
权重序列 = 1, q, q², …, q^(m-1)
width[j] = A * weight[j] / sum(weights)
```

W<=0 时不布局；W<b 时保留当前出现位置一页；取整时前 m-1 页向下取整，最后页接收剩余宽度。最小宽度约束只决定外层页宽，不能通过缩小字体解决页内内容过多。

参数验证要求 W 有限、q 有限且大于 1、g 有限且不小于 0、b 有限且大于 0；负宽、NaN 或无穷输入不进入坐标计算。

避免为非常深的 n 直接计算 q^n。通过逐步增长可见权重和判断最小页宽确定 m，之后仅计算 m 项；路径栏使用虚拟化，场景只实例化可见出现位置。

每个 PageOccurrenceView 独立持有缩放、滚动与高亮上下文。隐藏旧出现位置只释放或暂停它的渲染资源，不删除模型节点；用户返回时按出现位置恢复视口。初版允许重建隐藏图形，禁止一直保留全部深层 JavaFX 场景。

## 10 页内布局与正式图引擎

### 10.1 类型选择与几何协议

BuiltinPageTypes 提供具名内部实现：Point、Array、LinkedList、DoublyLinkedList、Tree、RedBlackTree、DirectedGraph、UndirectedGraph。二维数组与拉链哈希提供显式组合注册，不通过泛型名称自动识别。

每个 PageType 只声明自己的能力和布局策略。链表页、树页仍以 TopologyEdge 为真实关系，不向模型重新引入 left/right/parent 字段。TreeLayout 的展示入口由调用者指定或采用稳定节点 ID 作为默认入口；树的孩子顺序使用调用者提供的展示顺序或稳定 ID。方向、根入口和布局排序属于展示配置，不是 VM 结构字段。

真实树拓扑采用树布局；通用有向图和无向图使用 Stress。按 C13/C18 已落实的共享 AST 约定，Tree 页中某个 part 的宏拓扑若不是树，PartView 在提交布局前选择正式 GRAPH 引擎，页类型保持不变；独立 TreeLayout 仍拒绝非法树输入。RedBlackTree 仅增加节点业务颜色与文本，不新增指针解释。

先在 FX 线程测量文字、标题、内容与内部槽位，然后将以下纯数据交给布局：

- 外层展示单元的边界、节点位置 ID、端口和内部几何。
- part 内的拓扑边与展示顺序。
- 旧布局坐标、当前测量版本、视口约束及取消标识。

一个数组的内部节点共享其组合布局，通用图引擎只定位外层单元。PortRouter 将实际元素位置接到外层路径，使用数组边界与分隔线作为可用走线通道，避免穿越无关单元内部和文字。内部包含关系不绘制普通箭头。

各 part 单独布局，再纵向堆叠；不把互不连通的 part 交给引擎决定其纵向顺序。单值、颜色、高亮更新且尺寸不变时只重绘；拓扑、尺寸或组合变化才触发几何更新。

### 10.2 Graphviz 运行桥接

实现采用打包的 native Graphviz neato 作为首版 Stress 引擎，不引入浏览器或运行时 Node/Viz.js。C11/C23 已完成真实 native、宿主及发布 JAR 验证；结果见性能基准，不能直接沿用旧 WASM benchmark 的耗时。

Graphviz 官方说明 `mode=major` 使用 Stress Majorization，几何输出可用 `plain-ext` 保留边端口名称。[mode 文档](https://graphviz.org/docs/attrs/mode/)、[plain-ext 文档](https://graphviz.org/docs/outputs/plain/)。

锁定候选运行版本为旧验收基线 Graphviz 16.1.0；C11 提交必须取得可用 Windows x64 发行产物并重新验收。若该版本在目标环境不可用，只能记录实际替代版本、重新测试并更新运行清单，不能在不同版本下沿用旧结论。

开发环境通过显式配置读取仓库 `.local/tools/graphviz/<version>/bin/neato.exe`。发布时将完整运行目录打包到应用的 `runtime/graphviz/`；不得依赖用户 PATH。runtime 清单记录版本、平台、来源和实际校验值；保留发行包中的许可证和来源信息。[Graphviz 许可证](https://graphviz.org/license/)。

GraphvizProcessBridge 用 ProcessBuilder 参数数组启动进程，通过 UTF-8 stdin 传 DOT，不拼接 shell 命令。stdout 和 stderr 并行读取并限制错误输出大小，超时或取消时终止布局进程，关闭输入输出流。会话关闭时取消尚未完成的请求。

参数从既有验收基线开始：mode=major、maxiter=200、overlap=prism、sep=+10、splines=polyline、固定 start 种子。它们是首次测试参数，不是性能保证。part 已分开布局，不能把旧全图 pack 参数的结果直接当作当前分量排布结果。

DotGraphWriter 使用稳定、无业务文本的内部节点名，传入实际宽高和端口；业务文本由 JavaFX 绘制。引擎中的边统一不绘制箭头，箭头由 EdgeRenderer 根据原始 TopologyEdge 独立绘制。

PlainExtReader 验证图、节点和边数量、端口、控制点及所有数值；输出必须完整结束。Graphviz 几何单位为英寸、原点在左下，转为 JavaFX 逻辑像素时明确采用 96px/in 并翻转 Y 轴；控制点按其曲线协议解释，不能将它们误当节点序列。以上单位与输出规则依据[官方格式文档](https://graphviz.org/docs/outputs/plain/)。

首版同一对具体端口只存一条绘制边，重复 Connect 幂等，方向变更修改既有边。不同槽位或端口可以分别连线。自环等合法页内图输入必须经过正式引擎测试；旧 benchmark 未覆盖的输入不能写成已验收。

### 10.3 后台调度与稳定性

LayoutCoordinator 在后台调度，对同一目标取消或合并过期请求。几何缓存键包含页身份、geometryVersion、测量版本、可用宽度及引擎配置，不只用 pageId：同一页重复出现时可能有不同宽度。

容器提交版本与 geometryVersion 分开。颜色或访问变化不使几何缓存失效；布局结果到达时只要几何输入仍有效，就用最新样式应用该几何。拓扑、尺寸、页销毁、历史恢复和会话切换必须使相关旧结果失效。

历史恢复产生新的展示 epoch，避免旧后台请求覆盖回看的画面。计算失败保留最近有效几何并显示错误；新节点没有合法几何时显示明确待布局状态。不得静默换成另一算法后声称 Stress 通过。

旧坐标可用于初始化，但不能宣称它已保证增量稳定。C11/C13 要测节点增删、分量合并拆分、文字变长、整体翻转及位置变动。若实测仍不稳定，再在同一 LayoutEngine 契约内实施位移约束或局部布局。

### 10.4 样式约束

实现既有配色规范：绘图文字 #FFFFFF、不透明纯色、固定背景和边框；普通填充 OKLCH L 范围 0.40—0.46、C<=0.085；正文与标题白字对比度均>=7:1；标题从正文自动派生。

ThemeValidator 负责数值、色域与最终量化颜色校验；neutral/black 是具名例外，不能由调用者任意声明例外。节点圆角 6px，外层分组直角。高亮在既有边界内加粗或使用合法状态样式，不改测量尺寸、不用发光绕过规范。

主题注册和批量改色失败保留此前整批状态。不能允许适配器直接传任意 CSS、文字颜色或 JavaFX 样式对象绕过协议。

### 11.2 获取每步 Context

Stage 的独立 `captureLatestContext` 配置默认 false；CompilerApi 的 `setCaptureLatestContext` 提供 Stage、索引、类型三种入口。finishStep 在该配置为 true、已有 resultRecording 开启或最后一步时捕获 Context。未开启全步骤记录时，stepResults 仍按既定契约保留终态，不要求集合为空。

PipelineSession 开启当前上下文捕获，但保持既有“只保留阶段终态”的结果记录策略，不为了实时显示而保存所有步骤的完整上下文。默认非 Pipeline 调用者行为不变。测试分别验证 supplier 调用次数、lastStepResult 的 Context、stepResults 的保存数量和终态回看。

PipelineController 继续在既有单后台线程推进编译，通过 request 身份检查及 Platform.runLater 发布不可变 PipelineVisualizationFrame。布局另有几何版本，不把旧源码或旧阶段请求结果覆盖到新会话。

推进前保存 executedStage 的身份与索引，推进后读取 CompilerApi.lastStepResult()。该结果仍属于本次实际执行的阶段，不能用已经自动切换的 currentStage 给终态命名。成功和失败终态都保留；只有 Result.lastStep 且 Result.succeeded，并存在下一阶段时才轮换。nextStage 在 PipelineSession 中逐步调用同一推进与投影入口并检查取消；UI 可以合并中间发布，但不能跳过阶段终态捕获。

两槽的模型草稿、AST 槽位补丁及 source/core/结果位置映射一起放入 PipelineVisualizationSession 的内部 PreparedFrame。只有全部投影与校验成功后，才提交状态并发布整帧；候选内容不触发 FX、布局或外部监听。一侧失败保留上一帧并报告展示错误，不向 JavaFX 发布半步画面，也不把已成功的编译步骤重跑。PreparedFrame 记录原纯模型快照、位置值与适配器映射备份，提交异常时恢复全部现场展示状态；仅靠 VisualizationSnapshot 不足以恢复 AST 槽位。已消耗的 ID 不回收，恢复产生新的展示 epoch。两个容器之间没有 OwnershipBinding，输入输出的对应关系由 Pipeline 适配器管理。

投影或交接失败后，保留本次 pending Result/Context 并暂停新的编译推进。下一次操作只重试该投影，不能再次调用 compiler.step 或继续 nextStage 循环；成功提交后才允许消费下一步。这样既不会覆盖待处理 Context，也不会把展示重试误算为新的编译步骤。

| 静态分析 | source AST | core AST 及语义注解 |
| IR 生成 | AST 页 | 函数、基本块和指令序列 |
| 汇编生成 | IR 序列 | 汇编序列 |
| 对象生成 | 汇编与编码输入 | 节、符号、重定位及字节数组 |
| 链接 | 对象输入 | 链接结构与产物信息 |

输出内容按实际 Context 公共字段投影，不能为了示例伪造编译器未提供的数据。语法、静态分析及 IR 阶段均保留所需 AST 展示；IR 输出不是 AST 时，不把指令位置伪装成 AST 的 nxt。

每个 projector 显式注册 PageType。序列使用 PipelineArrayViewNode，AST 用 AstPageProjector；结构识别不进入通用容器。

### 11.4 AST 元数据迁移

用户确定位置由 AST 节点自身保存。本方案不用全局静态 side table 代替这两组位置。

保留 AstNode、Expression、Statement、Declaration 等接口。新增 AbstractAstNode 与 AstVisualSlots；将实际实现 AstNode 的 record 分批转为 final 普通类，继承 AbstractAstNode，业务字段仍为 final。原构造器、访问器和业务校验保持兼容。

equals/hashCode/toString 保留原业务字段语义，明确排除视觉槽位，避免移动位置破坏 map/set 查找。有节点同时实现多个 AST 接口，不能把这些接口全部改为抽象类。未实现 AstNode 的辅助 record 可以保留。

迁移前检索 record 解构、反射、构造器重载和复制逻辑；若使用了 AST record 解构模式，必须在同个迁移提交修改调用点并回归。编译期类型覆盖与原生/debugger 结果比对是迁移门禁，不能仅测 slots 赋值。

前两批迁移中 accessor 可以只由 AbstractAstNode 提供，待全部 AST 类型迁移完成再将 `visualSlots()` 加入 AstNode 的统一接口，避免中间提交存在未实现方法或临时抛错占位。

AstPageProjector 使用对象 identity 映射复用既有展示节点，通过 AstNodeComponents 遍历业务分量，保留分组声明等实际共享引用；不改变 AstChildren 的语义遍历约定。不能用 SourceRange 或 AST 结构相等作为唯一对象身份。TREE 页的连通宏拓扑确实是树时采用 TreeLayout，共享菱形或自环在请求构造时明确选择 GRAPH/Stress；缺少正式 Graphviz 仍报告错误，不能丢边来伪造树。

### 11.5 两槽交接与 source/core 映射

所有阶段都使用“上一输出成为下一输入”的统一轮换协议；第一阶段由源码输入启动，最后阶段完成后保留终态双槽供回看。仅静态分析和 IR 阶段开始时，附加一次 AST 的 `pre = nxt` 交接。具体顺序如下：

1. 用本次 executedStage 的最后一步结果保存终态双槽历史帧；成功且存在下一阶段时才标记下一阶段入口，失败则停留在当前终态。阶段交接使用阶段身份去重。
2. 在 PreparedFrame 中把上一输出标为新输入，保持容器身份与位置有效；暂不关闭旧输入，也不改现场 AST 槽或身份映射。
3. 为新输出预留全新容器身份并构建未激活的纯模型草稿。此草稿没有 JavaFX 宿主、监听、布局或活动会话登记，校验完成前不成为第三个活动展示容器。
4. 若进入 semantic/IR，为当前输入 AST 集合生成 `pre = nxt` 及清空待建立 nxt 的候选补丁；source/core 和结果映射也暂存。其他阶段只做通用轮换及失效位置清理。
5. 全部候选校验成功后，在串行发布边界提交模型与槽位、映射补丁，退休旧输入，激活新输出，在一次 FX 更新中完成双槽宿主切换。任意时刻最多两个活动展示容器。
6. 失败时丢弃候选输出、恢复旧双槽及适配器备份，阶段展示交接保持未完成，可从已捕获 Context 重试投影；不重执行编译，不复用候选消耗的 ID。

不能把旧输出的位置复制到 pre 后立即清空它所属的容器。旧输入关闭后的现场槽位必须失效，但历史帧保存的位置值不改。Panel 持有两个固定 UiVisualizationContainer，在同一 FX 调用中以 showSnapshot 发布双侧纯 DTO，同步清除旧几何并建立当前帧占位；异步布局只补充当前版本的画面。两侧不共享 JavaFX Node。纯模型草稿及备份只用于提交或回滚，不能作为第三槽展示。

SemanticResult 有 sourceProgram、core program 与 identity sourceToCore 映射。source 与 core 节点分别有自己的 slots；AstPresentationMapper 通过该映射查找当前有效输入或输出投影，不盲目把所有新 AST 的 slots 复制成旧对象位置。

IR 当前动作可能映射回 source 节点，适配器必须找到其有效 core 输入位置。AST 不出现在输出槽时允许 nxt 为空，IR 结果位置由 IrProjector 的对应表管理。AST 槽的 pre/nxt 表示输入输出位置，OperationPath 的 pre/nxt 表示同一容器内的归属两端，不能混用。

历史帧复制位置值和纯模型快照，不能在回看时再次读取已被下一阶段修改的 AST.slots。回看已完成阶段只恢复展示，不推进或倒退编译。

### 11.6 右侧 Pipeline 工作台

Starter 的既有 PipelineController 连接 EditorArea、AppFrame 右侧活动图标与 DisplayArea。PipelineSession 继续独占后台编译推进，PipelinePanel 负责双容器宿主、阶段选择、步骤说明和诊断展示；本轮不创建另一套编译流程，也不改变两槽轮换和终态历史协议。

画面标题以已发布 PipelineVisualizationFrame 的阶段与步骤为准。编译器进入下一阶段入口、但下一阶段尚未产生观察数据时，仍显示上一阶段终态，并在说明中明确标识下一阶段尚未开始。输入输出标题按该实际画面的阶段命名。历史回看支持返回当前阶段，仅修改选择，不消费编译步骤。

推进和历史选择共享忙碌边界：后台请求开始即禁用推进按钮、阶段列表与返回按钮，收到对应请求的完整快照后恢复。程序化修改阶段选择也须遵守忙碌限制，不能先改变选择再静默丢弃请求。

编译诊断使用可展开、可滚动、可选择复制的只读文本区。失败后回看其他阶段仍显示全局失败诊断，并注明真正失败的阶段。展示失败保留上一帧，说明重试不会重新执行已完成编译步骤；新源码准备时清除旧诊断与提示。

C26 新增 PipelineWorkbenchPresentationTest、PipelineControllerInteractionTest、PipelineWorkbenchFlowTest：分别验证画面语义与诊断、确定性的后台交互、真实右侧图标驱动八阶段及两侧布局。全部纳入累计门禁，不通过条件跳过规避真实 FX 和 Graphviz 验收。

### 11.7 AST 树契约与 IDE 卡片样式

AST 是树：`AstPageProjector` 以根节点广度优先遍历，只有对象的首次发现会写入父边，后续来自其他父节点或回指的引用不再生成边。所有对象仍各有一个展示节点，页面保持 `边数 = 节点数 - 1`、单根、可达，因此 TREE 页不会因共享引用降级成 Graphviz 图布局；解析和语义阶段每一步的布局都在进程内完成。`PartView` 的宏图树检查保留，用于拒绝真正带自环或环的页。

Pipeline 适配器统一通过 `PipelinePlans.card` 生成卡片，使用 `Preset.NEUTRAL` 表面。`ViewNodeRenderer` 对 NEUTRAL 卡片采用 IDE 暗色样式：正文 #161B22、标题条 #21262D、静止边框 #30363D、选中描边 #58A6FF、字段名 #8B949E、字段值与标题保持 #FFFFFF。彩色填充预设与既有配色协议不变，`NODE_BORDER` 仍是 #5A697E。

PipelineWorkbenchFlowTest 与 PipelineEndToEndVisualizationTest 在没有 Graphviz 进程参与的前提下要求 AST 页完成布局（GRAPH 引擎运行次数为 0、TREE 大于 0、无活动 native 进程），作为性能回归的确定性判据；PipelineAstTreeProjectionTest 覆盖跨父共享引用与真实编译器的逐帧树校验。

### 11.8 大规模输入的批处理与线性提交

`PipelineSession.nextStage` 在整阶段循环期间关闭逐步 Context 捕获，只在终态捕获观察并投影；中间帧按历史协议本来就会被丢弃，因此不再为它们拷贝词法 token 列表或重建整页。失败终态仍进入 pending，重试不消费新的编译步骤；`nextStep` 保持逐帧捕获与投影。`PipelineBulkProjectionTest` 用行数与 Context 计数把“终态投影一次”作为确定性的合同，`PipelineAtomicFrameTest` 对应更新为终态失败后重试。

`MutationTransaction` 由每命令整页拷贝改为批次粒度草稿：被触及页面首次复制为可变草稿，节点、组合、拓扑和就绪集合原地更新，提交时物化不可变页面并只做一次全局校验；组合深度仍由终态 `refreshSemantics` 复核。草稿维护父槽位索引与规范化端口对边索引，`ProjectionContainer` 的输入重放也用组合键集合判重，消除上万节点页面上的二次方扫描。`LargeBatchTransactionTest` 单批提交一万行数组并核对槽序。

该协议对含 STL 头的程序效果：Pipeline 模式八个阶段合计约 9.4s（纯编译 6.6s），词法 77898 步从逐帧投影的卡死降到约 0.62s，语法分析整阶段从 17.3s 降到 1.34s。

### 11.9 大规模页面的线性绘制

绘制与布局路径同样存在多处二次方扫描：渲染器按卡复制整页节点/主题映射；`LayoutRequest.Unit` 为每个端口线性扫描成员；`LayoutSupport.ordered` 与 `StressGraphLayout` 对每个排序项调用线性 `owner()`；`PortRouter` 为每条边重建完整障碍物列表；`PartView.paint` 逐项把卡片和连线加入画布，每次加入都触发子树事件级联。修复为：主题改按查找函数传递、端口校验用成员索引、排序与压力图用本地 owner 映射、整齐树页走行间通道路由（父行与子行之间的空带按构造保证无碰撞）、密集图用空间网格，`paint` 批量 `addAll` 挂载。

超长序列页（源码行、token、汇编、目标字节）保留头尾各 750 行与一条摘要行，显示上限 1501 项；词法高亮仍指向刚产生的 token（位于尾部窗口内）。文本排版度量按“字体+字符串”缓存。带 10 个 STL 头的程序实测：词法终态 54907 个 token 从界面挂死（约 171s、1.9GB）降到约 0.9s、144MB；26592 节点 AST 终态从约 289s 降到约 3.9s。

语义终态同时展示两棵数万节点的 AST，可见窗口还会持续重绘，因此 `AstPageProjector` 对超过 2000 个对象的树做折叠：焦点节点及其祖先完整展开，其余按广度优先预算保留，被折叠的子树在父节点上标注 `collapsed: N`；页面仍是单根连通树，位置交接与高亮对未显示节点保持容忍。带 STL 头的程序语义终态从 6.1s/2.1GB 降到 2.2s/592MB。

## 12 Debugger 集成

### 12.1 类职责

| 类或接口 | 单一职责 |
| --- | --- |
| RuntimeEventSink | 自制 VM 发布中立事件的出口 |
| RuntimeEventCollector | 作为 VM 唯一接收器收集有序事件，并隔离事件收集失败 |
| RuntimeEvent | 表达分配、读取、写入、复制、重分配和释放等成功运行事件 |
| RuntimeEventBatch | 保存一次执行区间的有序事件和上下文关联 |
| DebugMemoryReader | 从不可变 VM 状态读取注册结构所需数据，不触发新的 VM 访问事件 |
| DebugObjectIdentityRegistry | 管理 VM 对象、分配代次、地址与 ViewLocation 映射 |
| DebugStructureDescriptor | 保存调用者注册的类型、布局、字段偏移、步长和引用解释规则 |
| DebugStructureRecognizer | 后续自动识别特殊结构的接口 |
| DebugVisualizationAdapter | 将中立事件按已注册描述转换为容器命令 |
| DebugVisualizationHistory | 按 Debugger.Context.index 保存和读取可视化快照 |

RuntimeEvent、Batch、Sink 保持纯 Java，不依赖通用绘图模型。DebugRuntime 当前文件路径与包名不一致，本次只增加事件扩展点，不顺便迁移原有包。

### 12.2 VM 事件覆盖

事件必须从自制 VM 的实际操作出口发布，不能只对 RuntimeState 做前后 diff。diff 无法表达读取、同值写、同一步 alloc 后 free 或访问顺序。

| 运行路径 | 必须捕获的信息 |
| --- | --- |
| allocate / allocateZeroed | 分配身份、地址、大小、存储类别及初始化变化 |
| write / writeByte / 批量写 | 地址范围、访问顺序与成功写入 |
| read / 字节读取 | 地址范围及访问类型 |
| copy / 库函数直接拷贝 | 来源、目标、范围和最终变更 |
| reallocate | 旧址、新址、复制长度及旧分配释放 |
| 全局、静态初始化 | 初始化产生的分配与写入 |
| frame pop / 栈回收 | 栈区对象的生命周期结束 |
| free / delete 对应底层释放 | 分配身份与地址失效 |

所有绕过常规 write 的 System.arraycopy、allocation.bytes 修改和 memory.remove 路径都进入覆盖清单。事件只描述实际成功发生的 VM 行为；未启用监控时使用无操作 sink，避免创建无用事件对象。

VM 只连接内部 RuntimeEventCollector，不直接调用外部 adapter、监听器或可插拔 sink。收集边界捕获事件系统的 RuntimeException，记录展示诊断并暂停该区间监控，不能让已成功的 VM 操作因展示异常进入 Debugger.advance() 的程序 FAILED 路径。到停止点再把 Batch 与不可变 RuntimeState 交给 adapter，投影失败保留最近有效画面并报告展示错误；程序状态、内存和执行结果保持真实运行结果。收集不完整的区间明确标为展示未同步，禁止伪造完整访问日志。测试注入抛错收集存储及 adapter，与关闭监控的同程序比较 Stop、运行结果和内存。

每条事件有会话内顺序号，Batch 关联本次新产生的 Context.index。初始化区间同样有明确快照与事件边界。Adapter 从最终状态读取内容，同时保留有序事件用于访问高亮；一步内分配又释放的临时对象可以不留在最终图中，但不能在事件日志里丢失。

地址不能直接作为永久展示 ID。分配代次区分同地址的不同对象；内部字段以分配身份和偏移定位。重分配的身份转换由 descriptor 明确处理，旧址映射必须失效，不能让旧悬空指针自动指向新对象。

### 12.3 结构注册与历史

首版调用者显式注册节点页类型、字段读取、指针解释、数组步长及页绑定。运行时 malloc 信息本身不足以识别红黑树或拉链哈希。识别器后续命中后仍生成同一份注册描述，不直接操作 JavaFX。

同页 next 或图引用映射为 TopologyEdge；跨结构展开依赖映射为 OwnershipBinding。程序的合法页内环不触发归属错误。跨页展开产生节点归属环时，容器返回错误，adapter 保留最近有效展示并报告位置；不得修改 VM 内存或改变程序执行结果来迎合绘图约束。

真实执行事件只消费一次。Debugger.stepBack 或历史前进只恢复与 Context.index 对应的模型快照、映射和焦点，不重新运行特殊 IR、不重发分配事件。需要 IR 插桩的访问标记属于 debugger 侧扩展，不进入通用容器。

DebugVisualizationHistory 仅对当前调试会话负责。关闭会话时解绑 sink、取消布局并释放展示控件；程序执行完毕而仍允许历史浏览时保留快照。

### 12.4 调试工作台（右侧栏与右侧信息栏）

`DebugController` 复用 Pipeline 工作台的活动栏/展示区模式：右侧 DEBUGGER 图标切换工作台显示，打开时右侧信息栏与中心编辑区等宽（半屏，沿用同一 240ms 缓出动画），会话在单后台线程推进，FX 线程只消费不可变快照。工作台内部左半部分更宽（62%）用于可视化，右半部分上方是九个操作控件（开始、重启、到结束、下一步、上一步、步入函数、回退至调用处、到下一个断点、返回上一个断点），下方是栈区（80%）与堆区（20%）的可拖动分区；栈区为带滚动条的名称/值列表，堆区暂未实现。

“开始”之前只编译到 IR 并用 `DebugVariableRegistry` 按源码名检索变量定义：唯一命中直接进入捕获列表，多候选启用上一个/下一个/确定循环翻阅，列表项悬停可删除。点击“开始”后 `DebugProgram` 复制 IR 并为选中变量插入调试副本专用指令 `IrCaptureInstruction`：局部变量在声明后记录创建、读/写/取址前记录读取或写入、返回前记录离开作用域；全局变量在 `IrGlobalAddress` 的读写前记录。未选中的变量不插桩，程序语义、返回值与输出不变（`DebugCaptureTest` 对照验证）。

`Debugger` 执行捕获指令时不停止、不修改内存，只记录 `DebugCapture`（变量定义、访问类别、所在函数、访问点、捕获时存储地址），到停止点随 `Context` 一起发布；`DebugCaptureProjector` 用公开容器 API 投影：每个变量一张稳定身份卡片，值从停止点的不可变内存快照读取，创建/读取/写入映射为分配/读取/写入高亮，离开作用域删除卡片，历史回看只恢复检查点、不重放事件。结构自动识别不在本阶段：哈希表分层、字段展开与红黑树颜色等仍须由调用方按本节前面的显式注册契约提供描述符。

性能边界：手动“下一步/步入”每个途经上下文折叠一次捕获、只发布终态帧；“运行到结束”对中间止点只折叠捕获事件、不保留检查点，仅终态物化展示帧。

## 13 快照与线程约束

### 13.1 快照内容

VisualizationSnapshot 保存容器与根页身份、全部页初始化描述和类型键、节点 ROOT/OWNED 保留方式及内容、组合、拓扑、归属来源、就绪状态、父引用顺序与选择、焦点及源步骤版本。PageBindingRule 的完整定义、ruleId 来源和有效初始化保留信息必须保存，不能只保存已经展开的边；恢复后新分配仍须按原规则绑定，空页保留也须一致。不保存 JavaFX Node、AST 对象引用、VM 实例、进程或 executor。

恢复时从关系重建反向索引、引用数与 part，再验证不变量，不能直接信任序列化的派生计数。页类型工厂必须仍可通过类型键找到；缺失时返回明确错误，不用默认类型替代。

历史恢复保留原业务位置 ID，但分配器取现有高水位与快照已观察 ID 的最大值，不能倒退。新发布的 live revision 与展示 epoch 继续递增，历史的 source version 单独保留。

失败事务的结构、焦点、样式和已发布版本必须不变；ID 预留高水位允许继续增长。测试比较回滚结果时明确排除这一被允许的分配器变化。

### 13.2 线程边界

- 模型写入由一个串行执行器负责。公开调用提交批次并取得结果；不得持有模型锁等待 FX 线程。
- Pipeline 沿用现有后台推进线程；Debugger 事件在运行线程由内部收集器收集，到停止点形成批次。展示投影在运行异常处理边界之外执行，展示失败不改变程序执行状态。
- 布局接收不可变几何输入，在后台执行，不读取正在变化的 ViewNode。
- JavaFX 控件、测量、场景挂载和视口只在 FX 线程操作。
- 一个展示帧在一次 FX 发布中应用；旧 request、epoch 或几何版本返回时丢弃。
- 外部监听器只接收已提交描述；关闭方法可重复调用，解除监听、终止布局并释放 executor。

## 14 TDD 设计

### 14.1 流程与测试层次

每个功能按“写行为测试并确认 Red → 最小实现 Green → 重构 → 编译和累计验收 → commit”推进。Red 必须是预期行为未满足，不是语法错误、缺依赖或运行环境错误。测试和实现进入同一个通过门禁的 commit，不提交已知失败状态。

模型测试不启动 JavaFX。关系判据使用独立小图参考实现：DFS 验证归属、BFS 验证分量、删除前图计算存活集合。参考实现不调用生产 Store、Planner 或缓存，避免两个测试路径共享同一错误。

随机操作测试使用固定种子、小规模模型及可重放命令序列；失败记录种子和最小序列。它补充具体例子，不替代明确的需求测试。

### 14.3 三个必须保留的反例

**页环与节点环分开。** 先在三个页中构造 `R.r → A.a1 → B.b1 → A.a2`，得到四个出现位置，A 页有两次独立高亮。增加 `A.a2 → B.b1` 返回 OWNERSHIP_CYCLE，图、焦点和发布版本不变。

**桥与普通边分开。** 页内三角形删除一条边仍为一个 part；随后删除连接孤立分支的桥则分裂。结果与独立 BFS 的成员集合比较，不仅检查 part 数量。

**共享释放与强制删除分开。** `A→C←B` 中删除 A 保留 C，随后 B 释放才删除 C；显式 DeleteNode(C) 则立刻清除 A、B 的全部指向。测试同时检查父数组、下游集合、就绪/part 登记和页存活。

### 14.4 JavaFX 与真实引擎验收

JavaFX 测试复用现有 Platform.startup/runLater/Future 超时模式，Scene 操作全部在 FX 线程执行；不为了本方案引入 TestFX。测试进程必须显式开启 craken.ui.test，不能把发现但全部跳过当作通过。

验证 applyCss/layout 后的 bounds、箭头与槽位、纵向 part、滚动、窗口变窄、同页不同实例、关闭解绑。必要截图进入 build 下的验收产物；跨机器不要求文字抗锯齿逐像素一致。视觉检查覆盖常用缩放和实际节点内容。

Mock LayoutEngine 可用于调度和版本测试，但通用图引擎的 commit 必须通过真实 neato。正式运行时缺失或解析错误不得以 fixture 测试替代。旧 50/30、100/250 数据只作为新引擎对照输入，重新记录启动、协议、布局、解析与 FX 展示耗时。

### 15.1 新增 Gradle 任务

沿用 JavaExec 和 ConsoleLauncher，所有新增任务使用 Java 21 launcher、UTF-8、已有必要 export。

| 计划任务 | 范围 | 强制配置 |
| --- | --- | --- |
| visualizationModelTest | 模型、关系、事务、导航与快照 | visualization-model tag，fail-if-no-tests |
| visualizationLayoutTest | 几何、调度；C11 起包括正式引擎 | visualization-layout tag；C10 无需运行时，C11 起强制真实 neato |
| visualizationAdapterTest | Pipeline 与 Debugger 适配 | visualization-adapter tag |
| visualizationUiTest | 新组件的真实 FX 测试 | visualization-ui tag，子 JVM 属性 true |
| visualizationRegression | 当前受影响的既有 FX 测试 | 显式 class selector，子 JVM 属性 true |
| visualizationCheck | 当前实施阶段全部累计验收 | 编译、默认回归、必需套件及报告核验 |

任务只在已有真实测试时加入阶段门禁；未来尚未实施的套件不创建“零测试通过”占位。C01 起至少有真实 ID 行为测试和已有受影响 UI 回归。后续 stage 只能增加累计验收范围，不能为了提交删除必需测试。

所有 Console 任务使用独立的本次 runId 报告目录与 --fail-if-no-tests。AcceptanceReportVerifier 读取本次 XML，检查预期类存在、必需测试实际执行、失败/错误为零、必需 skipped/aborted 为零。现有基线中按条件跳过的无关旧 UI 测试单独统计，不能冲抵专用 UI 套件的要求。

### 15.2 每次 commit 的固定步骤

1. 新行为测试先 Red，并保存预期失败依据。
2. 实现与重构后编译生产、测试代码和资源。
3. 跑本阶段新增测试及截至本阶段累计的所有可视化验收。
4. 跑默认全量回归与列入清单的既有 UI 回归；涉及 VM/编译器迁移时不得省略原生与 debugger 行为测试。
5. 核验新报告、实际执行数、真实引擎版本及必要视觉产物。
6. 执行工作区和暂存区 diff 检查，审查仅属于本提交的文件。
7. 所有门禁成功后才 commit。门禁后若又改了源码、配置或测试，重新验收。

不能以“最后一个提交一起测”代替逐提交验收；不能用 --no-verify、关闭测试条件或沿用旧 XML 绕过失败。环境或依赖错误也不算通过。

### 15.3 统一入口

`scripts/verify-visualization.ps1` 接收累计清单中的实施阶段，生成 runId，执行编译和累计验收，并在首次失败时返回非零。阶段顺序按 acceptance-stages.json 的实际集成顺序；C00—C23 为首版，深度审计修复追加 C24、C25，C26 为未提交的右侧 Pipeline 工作台验收，C27、C28 为同批次的大规模性能修复，当前完整门禁使用 C28：

```powershell
./gradlew.bat --gradle-user-home .gradle-home --console=plain classes testClasses
if ($LASTEXITCODE -ne 0) { throw 'Compilation failed' }

./scripts/verify-visualization.ps1 -Stage C28
if ($LASTEXITCODE -ne 0) { throw 'Visualization acceptance failed' }

git diff --check
if ($LASTEXITCODE -ne 0) { throw 'Working diff failed' }

git diff --cached --check
if ($LASTEXITCODE -ne 0) { throw 'Staged diff failed' }
```

脚本将阶段与本次 runId 通过 `-PvisualizationStage=C28 -PvisualizationRunId=<runId>` 传给 Gradle，并调用 visualizationCheck。该任务按 acceptance-stages.json 选择截至该阶段的累计任务与预期测试类，将 runId 继续传给每个 Console 子任务，报告写入 `build/test-results/visualization/<runId>/<task>/`。缺少阶段、未知阶段或清单所需真实类缺失均返回非零。C10 的布局套件只要求结构几何；C11 起 StressGraphIntegrationTest 加入累计清单，之后每次提交都验证真实引擎。验收使用 --rerun-tasks 或同等明确执行策略，不允许仅用过期报告证明本次执行。

初次建立门禁前，现有可用默认回归入口是：

```powershell
./gradlew.bat --gradle-user-home .gradle-home --console=plain testWithoutWorker --args="execute --scan-class-path --fail-if-no-tests --reports-dir build/test-results/bootstrap --details=summary --disable-banner"
if ($LASTEXITCODE -ne 0) { throw 'Baseline failed' }
```

该命令默认不执行受条件控制的 FX 测试。需要在 C01 使用现有 UI 回归时，保存并临时追加 JAVA_TOOL_OPTIONS 中的 craken.ui.test=true，执行显式 select-class 后恢复原值；正式门禁则直接设置 JavaExec 子 JVM systemProperty，避免依赖环境技巧。

## 17 端到端验收脚本与完成条件

### 17.1 单例与红黑树

创建 Point 根页及 ROOT 单例；初始化 RedBlackTree 子页并以单例为锚点；空页首个树节点直接展示，后续分配进入 READY，连接后移入 part；访问树节点沿选中单例路径高亮。断链按分量拆分，节点不自动回 READY；显式删除单例后，仅无其他上游的下层节点级联释放。

测试使用无 left/right/parent 的展示边协议。调用者可通过展示顺序表达左右排列，但容器不解释指针字段。

### 17.2 共享与重复页

构造两个上游共同指向一个下游，交替访问改变 index；验证只展示选中链。再构造合法的 `R → A.a1 → B.b1 → A.a2`，验证重复 A 模型只有一份、两个控件和高亮独立。

删除某个选中上游时顺延；同批删除其全部可选父时沿删除前路径回退。任何地方都不以 pageId 去重或对页图套引用计数。

### 17.3 Pipeline 与 Debugger

Pipeline 短源码依次完成八阶段，验证双槽、源码变更取消、AST 交接、分栏保留、已完成阶段回看。默认编译路径不产生展示控件，也不因捕获配置改变原输出。

Debugger 短程序覆盖分配、连接、同值写、读取、拷贝、重分配和释放；事件 fixture 与真实运行结果对照；回退与前进只恢复历史。可视化拒绝一个非法归属循环后，原程序的 VM 执行结果保持一致。

- 第 3 节所有不变量在明确例子、固定随机序列和真实运行中成立。
- 当前阶段累计测试及默认回归全部通过；必需 FX/真实引擎用例未跳过。

## 19 实施落地约定

前文保留设计阶段的职责划分，实际源码进一步明确以下边界：

| 实现 | 职责与可观察行为 |
| --- | --- |
| visualization/style/ColorSpec、ColorValidator | 纯 Java 色值与唯一颜色校验入口；模型提交及快照恢复均先验证，UI ThemeValidator 委托它 |
| snapshot/SnapshotValidator | 在恢复前验证完整身份、关系、规则来源、组合、存活和配色；SnapshotCodec 负责值编码及派生状态重建 |
| PageTypeRegistry / ViewNodeContract | 初始化时冻结页类型元数据与嵌套策略回调；每次工厂和节点复制调用验证身份、内容、保留方式、父选择及组合子节点。自定义回调须纯函数，不得捕获可变业务对象 |
| PageLayoutHints / SetPageLayout | 保存同页存活节点的显示根及部分顺序；组合成员归一到宏单元，未显式排序者追加稳定 ID，快照与历史保留提示 |
| TopologyEdge / EdgeStyle | 保存具体节点端口及独立线色/箭头色/标签；同一具体端口对幂等更新，不同端口对保留独立边；颜色更新不修改几何协议 |
| ContainerModel.sourceVersion | 保留历史来源版本；live version 与 epoch 在恢复时递增，两者不能混为同一个字段 |
| GraphvizRuntimeLocator | 显式配置优先；安装包从自身 JAR 的 lib 上级定位 runtime/graphviz，开发目录使用锁定 .local；不依赖 cwd 或全局 PATH 找发布运行时 |
| LayoutCoordinator | 默认两 worker、最多 64 份几何缓存；发布前再次检查 occurrence/part/request 身份，旧结果不可覆盖新画面 |
| PartView | 将一个 part 测量为宏单元与实际成员端口；无连线单宏节点直接 POINT，非树宏拓扑使用正式 GRAPH |
| StressGraphLayout | 只有实际连线使用内部成员或固定端口才执行 PortRouter；未使用的注册端口不触发二次路由 |
| DebugMemoryReader / DebugObjectIdentityRegistry | 分别读取初始化掩码与分配代次内存、维护对象/指针代次和展示身份，旧地址复用不能复活旧引用 |
| DebugVisualizationHistory | 按 Context.index 恢复纯值画面及身份 checkpoint，不执行 VM；有界淘汰可选，末态保持到显式关闭 |

Pipeline 生产适配代码位于 `craken.visualization.adapter.pipeline`，UI 编排位于 `craken.ui.pipeline`。105 个实际 AstNode 实现已分三批迁移，业务构造、访问、相等与模板复制契约保留；AstNodeComponents/AstNodeConstructor 描述原业务分量，视觉位置不进入 equality/hashCode。

Debugger 的结构描述、手动登记和识别仍由调用方负责。VM 的 record/accept/drain/withoutEvents 在执行线程调用；只有 collector.close 支持显示线程关闭，在途工厂可结束但其事件不再发布。不完整监控区间明确返回未同步诊断，不补造访问历史。

无参 UiVisualizationContainer 拥有 session，传入 session 时借用；DebugVisualizationAdapter 默认拥有 session，三参构造可明确借用。历史宿主只显示 DTO，不反向修改活动会话。所有关闭入口按所有权释放资源并防止迟到布局或编译结果发布。

基准分开记录原生进程、Java worker CPU、FX 准备、发布回调及实际 Scene 坐标变化；这些数值不等同显示器呈现耗时。完整数据及限制见可视化性能基准.md。首版范围仍不包含 READY 可滚动列表、自动结构识别器或三维可视化。

| 边界 | 修复后的契约 |
| --- | --- |
| 扩展页类型 | 页类型元数据不再受调用者可变集合或标志影响；同一已注册定义可跨调用方注册表和会话注册表复用。工厂不得预填未登记的 children，复制不得暗改内容、身份或绑定 |

## 21 C25 生产路径复查与边界补正

C25 从 `462daf3` 再次独立核对实际调用链，重点验证先前单模块测试未覆盖的组合行为。核心新增以下明确约定：

- 事务中的显式 DeleteNode 仍延迟到提交阶段执行级联，但其旧组合槽可被后续 Compose 复用。只有已显式删除的旧成员让出槽位；存活成员冲突仍报错，整个批次仍原子提交。
- ModelChangeSet.pages 包含被添加、撤销或删除的归属关系两端页，以及规则两端页；即使另一个来源仍保留有效绑定，来源登记的变更也要报告。
- 活动会话恢复快照时逐次校验页工厂与节点复制结果，并要求重建后的自定义高亮集合与捕获值一致。错误输入不能在恢复中被静默丢弃；只读历史 DTO 保留自己的捕获值，不调用业务页工厂。

生产适配与绘制补正：

- DebugStructureDescriptor.Reference 的 TOPOLOGY 默认从 `field:<name>` 指向目标 `node`，也可显式指定两端端口。同一具体端口对聚合方向，互反方向合为 BOTH；不同指针字段保留独立边。适配器比较规范化后的端点、端口与方向，未变化的边保留关系 ID，方向变化使用原边更新。
- 引用字段进入节点展示内容；同名 scalar/reference 仅允许描述同一偏移上的 POINTER 字段。数组元素的 minimumSize 不得大于 stride，也不能越过声明的数组对象范围；实际 VM 分配更大不豁免描述错误。数组保留外层身份、重新创建成员时，先删除旧成员再组合新成员。
- Pipeline 比较 AST 边时采用核心相同的端点顺序与反向规则，共享节点不会使静态边每一步都重新分配 ID。
- Lexer 保留当前步骤在预处理后文本中的真实扫描范围，PipelineStepObservation 将它捕获为 expandedSourceRange；词法输入按该范围高亮，输出按刚产生的 token 身份高亮。宏映射、include、多行注释和诊断不能用原始源码行号或猜测的 lexeme 长度替代；Stage.Result 的 IDE 原始源码范围保持不变。
- PartView 的连线显示在组合背景上方，具体端口与避障几何保持不变，内部单元间的边不会被外层不透明卡片覆盖。LayoutCoordinator 即使某资源关闭抛出 Error，也继续关闭剩余资源，再报告原始异常。

模型、适配器、UI 的新增反例与最终累计验收结果见实施记录。正式门禁已追加 C25，后续提交继续累计执行前面全部必需测试。
