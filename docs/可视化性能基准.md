# 可视化性能基准

## C11：原生引擎与调用边界

2026-10-05，Windows 11 amd64、JDK 21.0.10、官方 Graphviz 16.1.0，种子 42。每组预热一次、测量三次。开发期间的同机测量，不能当作固定延迟承诺。原始 JSON 保存在布局独立工作区 `build/verification/graphviz-native-benchmark.json`；主工作区执行下列命令可生成新的报告。

```powershell
./gradlew.bat --gradle-user-home .gradle-home --console=plain benchmarkVisualizationGraph
```

`nativeProcessMs` 包含进程启动、neato 执行和管道传输；独立 `-V` 启动探针为 65.38 ms，未从布局时间中扣除。该工具不加载 JavaFX，FX 测量与绘制另行记录。

| 输入 | 调用方式 | 无向总时间均值 | 有向总时间均值 |
| --- | --- | ---: | ---: |
| 50 节点 / 30 边 | 整图一次，仅作对照 | 496.40 ms | 534.78 ms |
| 50 节点 / 30 边 | 22 个 part 串行，每 part 一次 | 11779.94 ms | 12215.00 ms |
| 100 节点 / 250 边 | 一个连通 part | 705.45 ms | 741.95 ms |

100/250 的协议编码约 0.45 ms，输出解析约 1.3 ms。全部 24 个测量样本节点重叠数为零，结束后的活动进程数为零。

该结果揭示了逐 part 启动进程的成本。容器宿主应对没有连线的单点 part 使用直接定位，对有边图保留正式引擎，并采用有界并发、缓存和过期结果取消。上述原始串行结果应保留，不能以整图对照数值冒充产品路径耗时。

## 增量几何稳定性

对共同节点减去整体平移后，100/250 增加一个连接节点：平均位移 123.50 px，P95 266.94 px，最大 407.32 px；删除该节点得到同量级位移。一个节点文本测量宽度增加 180 px：平均 18.19 px，P95 51.89 px，最大 132.24 px。因此当前重排不能称为增量稳定布局。

基准同时记录合并/拆分 part，以及非退化三角形的朝向变化。后者也会由局部形变造成，不能据此断言整个图发生翻转。不同 part 的局部坐标比较未包含 UI 纵向排布，不可用作屏幕位移结论。

## C23：真实宿主展示验收

2026-10-05，在相同 Windows/JDK/Graphviz 环境中使用 JavaFX 21.0.2、真实 Stage、800×600 Scene、zoom=1、种子42。每个输入和方向预热一次，再测三次；每次使用新的宿主、协调器和几何缓存，JVM/操作系统文件缓存已经预热。50/30 与 100/250 的拓扑沿用原生基准，但节点尺寸来自实际文字/字段卡片测量，不能直接等同 C11 的合成矩形。

```powershell
./gradlew.bat --gradle-user-home .gradle-home --console=plain benchmarkVisualizationHost
```

复现入口编译 `src/benchmark/java/craken/ui/component/visualization/VisualizationHostBenchmark.java`，输出 `build/verification/visualization-host-benchmark.json` 及两张截图。以下为主分支本次运行的12个首次展示样本均值，单位ms：

| 输入/方向 | part / native调用 | 展示完成墙钟 | 最后FX准备 | FX发布回调总计 | Java布局worker CPU |
| --- | --- | ---: | ---: | ---: | ---: |
| 50/30 无向 | 22 / 6 | 1643.13 | 25.06 | 19.71 | 31.25 |
| 50/30 有向 | 22 / 6 | 1553.28 | 9.76 | 11.46 | 36.46 |
| 100/250 无向 | 1 / 1 | 840.53 | 6.55 | 7.05 | 20.83 |
| 100/250 有向 | 1 / 1 | 820.39 | 4.84 | 7.91 | 10.42 |

稀疏输入的16个无连线单点使用直接POINT定位，6个有边part使用正式native布局，观察到的native并发峰值为2。12次纯Touch更新全部为0次native重跑，分别命中22份或1份几何缓存。所有样本核验了完整节点/边覆盖、有限几何、宏节点无重叠；每次宿主关闭后观察到0活动worker和0native进程。

首轮测量暴露了额外路由开销：节点虽注册了north/east/field等端口，普通边仅使用宏节点AUTO端口，旧判断却触发PortRouter。C23以真实native曲线相等性先获得Red，再改为只判断实际连线引用的端口，并保留固定端口与内部成员回归。修复前同机100/250首次展示均值为2682.68ms（无向）和3149.67ms（有向），Java布局CPU约1807/1953ms；优化后的主分支结果见上表。原始首轮串行和额外路由成本都保留，不从历史数据中删除。

计时含义：展示墙钟从FX构造/刷新开始，到当前几何发布且FX layout刷新完成；不包含fixture生成，不代表显示器呈现时刻。FX准备包含控件创建、CSS、字体测量与请求构造，没有伪拆成单独测字耗时。worker墙钟包含等待子进程，CPU不包含native子进程CPU；并发worker累计墙钟可以超过端到端墙钟。Windows线程CPU计时较粗，小回调可能读到0。JSON保留完整CPU、队列等待、engine/cache计数和几何数据，表格不能视为固定时延承诺。

### 实际 Scene 增量位移

以下使用FX layout后的节点 `localToScene` 坐标，包含part纵向排列，比较共同节点并减去整体平移；这比C11的part局部坐标更接近实际展示。

| 操作 | 展示墙钟 | 位移P95 | 说明 |
| --- | ---: | ---: | --- |
| 增加连接节点 | 808.58ms | 246.66px | native重新布局 |
| 删除新增节点 | 62.99ms | 246.66px | 复用原图缓存，仍有恢复位置的移动 |
| 增大实测文本宽度 | 757.65ms | 63.10px | 宽度变化触发新几何 |
| 合并part | 510.33ms | 534.74px | 2个part变为1个 |
| 拆分part | 488.28ms | 2688.61px | 2个part变为3个，纵向顺序也影响位移 |

当前实现不能称为动态位置稳定布局。性能优化解决了未使用端口造成的多余计算，没有解决图形变化后的重排；未设置或宣称通过固定延迟、位移阈值。

真实Stage截图为 `build/verification/visualization-host-600.png` 与 `visualization-host-1200.png`。实际Scene宽分别600和1200.6666，高720；后者受Windows DPI取整影响。截图使用约0.274/0.278缩放以展示100个节点和250条边的全貌，常规交互默认zoom=1并允许滚动。已目视核验完整宿主、白字、不透明填充、路径栏和连线。
