# 编辑器补全方案

日期：2026-10-07

目标：在编辑过程中给光标处提供关键词、头文件和变量名候选，用光标浮窗展示，选中后只替换光标左侧的前缀，不自动改写其余源码。触发方式为“随输入自动弹出 + Ctrl+Space 强制展开”，与重构前 `minic` 包时代的补全体验对齐。

## 1 历史参照

重构前的实现位于 `7bd6efa FEAT：补全编辑器提示并修复光标体验`（`minic` 包时代）。旧实现用一个 `ContextMenu` 展示最多 9 条候选：关键词、正则匹配的声明名、全文标识符和 `printf` 等常用外部符号，Ctrl+Space 强制触发，Enter/Tab 应用，Esc 关闭。当前编辑器迁移到 RSyntaxTextArea 后，这些能力没有迁移过来，只剩通用 C 高亮。

## 2 现状复用

- `UiCodeEditor.showCaretList(...)` 已有完整的光标浮窗：按主题渲染、光标锚定、上下/翻页/Enter/Tab/Esc 键盘处理和窗口边缘翻转布局。
- 编译器 `Lexer(SourceFile).lex()` 提供一次性词法入口：注释和字符串字面量不会产出标识符 token，词法规则与前端一致；非法输入只产生诊断、不抛异常。
- `lib/*.mh` 与 `lib/stl/*.mh` 是系统头文件目录，`SystemLibraryCatalog.includeRoot()` 给出库根目录，`StlHeaderCatalog` 确认 `<vector>` 这类裸名与 `__` 内部实现、`bits/stdc++.h` 捆绑包的对应关系。
- `RealtimeSyntaxController` 提供了“Swing 文档监听 -> 后台合并计算 -> FX 线程交付”的成熟模式，补全沿用同一套线程与生命周期约定。

## 3 类设计

| 类 | 单一职责 |
| --- | --- |
| `CompletionKind` | 候选来源：KEYWORD / VARIABLE / HEADER |
| `CompletionCandidate` | 冻结一条候选：插入文本 + 来源类别 |
| `CompletionContext` | 光标上下文：IDENTIFIER / INCLUDE_ANGLE / INCLUDE_QUOTE |
| `CompletionPrefix` | 光标左侧待替换区间与上下文，Java 字符下标半开区间 |
| `CompletionResult` | 一次计算结果：前缀 + 按展示顺序排列的候选 |
| `CompletionCatalog` | 数据源：关键词名单、尖括号与引号两种头文件名单；可由库根目录和源码目录生成 |
| `CompletionEngine` | 纯 Java 计算：判定上下文、提取标识符、按前缀过滤候选 |
| `EditorCompletionController` | 每视图粘合层：Swing 文档/光标/焦点事件、后台合并线程、FX 浮窗交付、选中替换与资源释放 |

`CompletionEngine` 不依赖 JavaFX，可在测试里直接构造完整源码与光标偏移验证；`EditorCompletionController` 只在编辑器视图存活期间存在，由 `EditorFile` 创建并在关闭时释放，分屏视图各自独立、共享同一份文档。

## 4 候选来源与过滤

- 关键词：与 `Lexer` 接受的关键词一致（C 基础类型/修饰符/控制流、字面量、C++ 扩展和替代运算符拼写），按固定顺序展示。
- 头文件：光标位于 `#include <` 之后时给出 `name.h`（lib 根目录）与 STL 裸名（`lib/stl`，含 `bits/stdc++.h`）；位于 `#include "` 之后时给出本目录与库根目录的 `name.mh` 拼写。`__` 开头的内部实现不进入名单，头文件名单在控制器创建时收集一次，不在每次按键时读盘。
- 变量名：对当前缓冲区跑一次 `Lexer.lex()`，收集全部 `IDENTIFIER` token，排除关键词、`#` 开头预处理指令行上的名字，并按首次出现顺序去重。注释、字符串、字符字面量里的文本天然不会成为 token。

过滤统一为大小写敏感的前缀匹配；与已输入前缀完全相同的候选不再重复展示。字符串/字符字面量、注释内的光标不产生候选；注释掉的 include 行同样不产生候选。

## 5 上下文与触发

前缀判定只扫描当前行：include 行按 `^\s*#\s*include\s*[<"]...` 识别尖括号/引号上下文，普通代码按 `[A-Za-z_0-9]` 回扫标识符。自动弹出条件是“include 上下文”或“非空标识符前缀”；Ctrl+Space 强制展开（空标识符前缀时给出关键词加变量全量）。浮窗打开时跟随光标刷新候选，普通点击不主动弹窗；失去焦点关闭浮窗。

选中的候选项替换光标左侧前缀：`CompletionEngine.prefixAt` 在应用时用当前文档重新计算替换区间，插入后光标落在新文本末尾，并且本次插入不会立即再次弹出。头文件上下文只替换 `#include <` 之后的名字，尖括号/引号本身留给用户继续输入。

## 6 线程与生命周期

- 文档监听在 EDT 上入队；由于 `DocumentListener` 先于 `DefaultCaret` 移动光标触发，取样延迟到本轮 EDT 事件之后，保证前缀来自插入后的最终光标位置。
- 单守护线程合并式计算：只取队列最新请求，交付前再校验请求号，过期结果丢弃。
- 交付在 FX 线程，浮窗自身的文档版本校验继续兜底：文档已变化时旧列表不会显示、旧选中不会应用。
- 每个 `EditorFile` 视图持有一个控制器；`dispose()` 时移除 Swing 监听和 Ctrl+Space 绑定、关闭线程并清空浮窗。只读编辑器不取样、不应用。

## 7 TDD 与验收

1. `CompletionEngineTest` 先要求：关键词前缀、大小写敏感、声明名按首次出现顺序、预处理行名字不泄漏、尖括号/引号两种头文件上下文、字符串/字符/注释不补全、完整关键词不重复、空前缀给出关键词加变量、库目录名单排除 `__` 内部实现。纯 Java，无窗口依赖。
2. `EditorCompletionControllerTest` 在真实窗口里验证整条链路：输入 `wh` 回车得到 `while`；Ctrl+Space 加回车插入首个关键词；`#include <st` 回车得到 `stdio.h`；输入 `cou` 回车插入已声明的 `counter`。仅 `craken.ui.test=true` 时运行。
3. 回归门禁：两个测试类分别纳入 `visualization-model` 与 `visualization-ui` 标签套件；实施完成后模型套件 143/143、UI 套件 53/53、默认回归 708/708 全绿。

实施中还修复了 `DocumentListener` 取样早于 DefaultCaret 移动导致的“前缀少一位”问题：文档变更请求经 `SwingUtilities.invokeLater` 延迟到光标更新之后，关键词与变量名补全由此可用。
