## mov
当前汇编文本是 `${text}`，对应的 C 源码片段是 `${source}`。mov 负责复制数据，它把立即数、寄存器里的值或内存中的值送到另一个寄存器或内存位置。像 `x = add(x, 2);` 这样的语句，在调用前后常需要用 `mov` 把参数、返回值或局部变量搬到合适的位置；结构体字段和数组元素访问，也常先把某个地址或取出的值移动到寄存器里再继续处理。Windows x64 的很多运算更喜欢先把数据放进寄存器这张“临时草稿纸”，而且某些指令不能直接从一个内存位置复制到另一个内存位置。看 `mov` 时要特别注意左右两边谁是来源、谁是目的地，以及它是在准备计算、保存结果，还是在配合调用约定传递参数。

## arithmetic
当前汇编文本是 `${text}`，对应的 C 源码片段是 `${source}`。算术指令把 IR 中的整数运算落到真实寄存器或内存地址上，例如加法、减法、乘法，以及进入或离开函数时对栈指针的调整。`return a + b;` 可能会先把 `a` 和 `b` 放进寄存器，再用加法指令得到返回值；数组访问或结构体字段访问也可能用加法把基地址和偏移量合成真正要读写的位置。Windows x64 的 CPU 不会理解 C 表达式的整体含义，它只会按这些短指令一步一步改变寄存器或内存中的数。读这类行时，要盯住“哪一个值被改了”，因为很多算术指令会把结果直接写回其中一个操作数。

## compare
当前汇编文本是 `${text}`，对应的 C 源码片段是 `${source}`。比较指令通常对应 C/IR 里的条件表达式，比如 `if (1 < 2)` 或 `while (x < 5)` 里的 `<`。在 Windows x64 汇编里，`cmp` 或 `test` 一般不会直接生成一个叫“true/false”的普通变量，而是改写 CPU 里的标志位。紧跟着的条件跳转会读取这些标志位，决定是进入 then 分支、跳出循环，还是继续执行循环体。学生看比较指令时，最好把它和下一条或附近的条件跳转连起来看，因为单独一条 `cmp` 只是“做判断前的量尺”，真正改变控制流的是后面的 jump。

## jump
当前汇编文本是 `${text}`，对应的 C 源码片段是 `${source}`。跳转指令负责改变下一条要执行的汇编行，标签就是它要去的路标。无条件跳转通常对应 IR 里“这个基本块结束后直接去下一个块”，条件跳转则常和前面的 `cmp`/`test` 一起实现 `if (1 < 2)` 或 `while (x < 5)`。Windows x64 的 CPU 默认只会往下执行下一行，如果想表达分支、循环或提前离开某段代码，就必须用跳转把执行路线改过去。看 jump 时要同时关注条件和目标标签：条件告诉你为什么跳，标签告诉你跳到哪一段 C/IR 逻辑。

## call
当前汇编文本是 `${text}`，对应的 C 源码片段是 `${source}`。`call` 通常对应 C/IR 里的函数调用，例如 `x = add(x, 2);` 或 `printf("value=%d\n", 42)`。在 Windows x64 调用约定里，前几个整数或指针参数通常要放到 `rcx`、`rdx`、`r8`、`r9`，调用前还常会看到为栈空间和对齐做准备的指令。`call` 执行时会跳到被调用函数，函数结束后通常把返回值放在 `rax`，调用者再把它保存到变量或继续参与计算。学生看调用附近的汇编时，不要只盯 `call` 本身，还要看它前面怎样摆参数、后面怎样接住返回值。

## ret
当前汇编文本是 `${text}`，对应的 C 源码片段是 `${source}`。`ret` 表示当前函数的汇编代码执行到终点，它会回到调用者当初执行 `call` 之后应该继续的位置。像 `return a + b;` 这样的 C 语句，真正的加法通常已经在 `ret` 之前完成，返回值也通常已经按照 Windows x64 约定放进 `rax`。在 `ret` 前面，编译器还要把栈指针和需要恢复的寄存器整理好，让调用者回来后仍然像什么都安排妥当一样继续运行。读到 `ret` 时，可以把它看成函数的“退场口”，重点检查返回值是否已经准备好，以及函数进场时借用的栈空间有没有还回去。

## stack
