## AUTO
`{{root}}` 的类型是 `{{typeName}}`。AUTO 表示 MiniC 会先观察运行时值的形状，再决定把它画成标量、数组、指针或结构体。C 代码里你写的是 `{{cExpression}}`，也就是先从根变量 `{{root}}` 出发看它现在到底装着什么。例子：`int x = 7;` 会更像一个单格值，`int a[3];` 会更像一排格子，`struct Point p;` 会更像带字段的小表。类比一下，AUTO 就像老师先看题目类型再选解题图，不要求你一开始就背每一种画法。读图时先看根变量、类型和摘要，再顺着元素说明理解每一格、每个字段或每条箭头对应哪段 C 代码。

## SCALAR
`{{root}}` 是一个普通标量值，类型是 `{{typeName}}`。它在 C 代码中通常像 `int count`、`char ch` 或一次表达式 `{{cExpression}}`，可视化会把重点放在“变量名、当前值、地址和变化”上。例子：`count = count + 1;` 执行后，旧值可能是 `{{oldValue}}`，新值是 `{{newValue}}`，说明同一个左值路径 `{{lvaluePath}}` 被写入了新内容。类比一下，标量像一张只写一个数字的小便签，地址 `{{address}}` 是这张便签放在内存抽屉里的位置。看这种图时，不必找箭头或下标，主要确认这个名字在当前步骤保存了什么值，以及 C 代码哪一处读写了它。

## POINTER
`{{root}}` 是指针，类型是 `{{typeName}}`。在 C 代码里，指针变量本身保存的不是普通整数含义，而是另一个对象的地址；表达式 `{{cExpression}}` 代表当前正在观察的指针或解引用位置。例子：`int *p = &x;` 中，`p` 这一格保存 `x` 的地址，`*p = 7;` 才是沿着箭头走到目标再写值。类比一下，指针像一张写着“去 stack:0x24 找”的纸条，`{{pointerTarget}}` 就是纸条指向的门牌号。读图时先看 `{{root}}` 自己的地址 `{{address}}`，再看箭头终点；这能帮你区分“改 p 这张纸条”和“通过 *p 改目标对象”。

## POINTER_CHAIN
`{{root}}` 是指针链，类型是 `{{typeName}}`。C 代码中常见写法像 `int **pp`、`node->next->next`，一个指针指向另一个指针或结构体，再继续指向下一层；当前表达式是 `{{cExpression}}`。例子：如果 `pp` 指向 `p`，而 `p` 指向 `x`，那么 `**pp` 才会读到或写到 `x` 的值。类比一下，这是一串传话纸条：第一张纸条告诉你找第二张，第二张再告诉你找真正的数据。图里的每条箭头都表示一次解引用，`{{pointerTarget}}` 是当前箭头的目标地址。读图时按箭头一层层走，不要跳步，这样能避免把 `p`、`*p` 和 `**p` 混在一起。

## ARRAY
`{{root}}` 是数组，类型是 `{{typeName}}`。C 代码里数组访问通常写作 `{{root}}[i]`，当前元素表达式可能是 `{{cExpression}}`，下标路径是 `{{indexPath}}`。例子：`values[1] = values[0] + 2;` 会让图中第 1 格显示新值，旧值 `{{oldValue}}` 到新值 `{{newValue}}` 的变化对应同一个左值 `{{lvaluePath}}`。类比一下，数组像一排编号从 0 开始的储物格，变量名 `{{root}}` 是整排柜子的名字，下标告诉你打开哪一格。读图时沿着格子顺序看，特别注意 C 语言下标从 0 开始，`[1]` 是第二格。

## MATRIX
`{{root}}` 是二维矩阵或二维数组，类型是 `{{typeName}}`。C 代码里它常写成 `{{root}}[row][column]`，当前元素表达式是 `{{cExpression}}`，下标路径是 `{{indexPath}}`，行列位置是第 `{{row}}` 行、第 `{{column}}` 列。例子：`matrix[1][0] = 5;` 会落在第 1 行第 0 列，而不是线性数组的一维位置。类比一下，矩阵像教室座位表：先找第几排，再找这一排的第几个座位。读图时先看行，再看列，把 C 表达式里的两个方括号和图上的二维格子对应起来；这样能减少把行列写反的错误。

## POINTER_ARRAY
`{{root}}` 是指针数组，类型是 `{{typeName}}`。C 代码里它常像 `int *items[3]` 或 `struct Node *children[2]`，每个格子本身又是一张地址纸条；当前元素表达式是 `{{cExpression}}`，下标是 `{{indexPath}}`。例子：`children[0]->value` 先取第 0 格里的指针，再沿箭头访问结构体字段。类比一下，普通数组的格子里放物品，指针数组的格子里放取物品的地址卡。读图时先按下标找到格子，再看格子里的 `{{pointerTarget}}` 指到哪里；这能区分 `children[0]` 和 `*children[0]`。

## STRUCT
`{{root}}` 是结构体，类型是 `{{typeName}}`。C 代码里结构体字段访问通常写作 `{{root}}.field`，当前字段表达式可能是 `{{cExpression}}`，字段名是 `{{fieldName}}`。例子：`point.x = 7;` 表示修改 `point` 这个结构体里的 `x` 字段，而不是创建一个叫 `x` 的独立变量。类比一下，结构体像一张表格或学生档案，`x`、`y`、`next` 这些字段是同一张档案上的不同栏目。读图时把每一行字段和 C 代码里的点号访问对应起来，再结合地址 `{{address}}` 理解字段值放在结构体内部。

## STRUCT_POINTER
`{{root}}` 是结构体指针，类型是 `{{typeName}}`。C 代码里常见访问方式是 `{{root}}->field`，它等价于先 `*{{root}}` 找到结构体，再用点号访问字段；当前表达式是 `{{cExpression}}`。例子：`node->value = 10;` 不是改指针变量 `node` 自己，而是沿着 `node` 保存的地址 `{{pointerTarget}}` 找到结构体对象，再改它的 `value` 字段。类比一下，结构体指针像一张写着档案柜位置的卡片，箭头 `->` 表示拿着卡片去柜子里找那份档案。读图时先确认指针是否为 NULL，再看它指向的结构体字段。

## STRUCT_POINTER_CHAIN
`{{root}}` 是结构体指针链，类型是 `{{typeName}}`。C 代码里常见形态是 `head->next->next` 或 `tree->left->right`，每一步 `->` 都表示沿着一个指针字段继续走；当前表达式是 `{{cExpression}}`。例子：链表中 `head->next->value` 先从头结点走到 next 结点，再读那个结点的 value。类比一下，它像顺着路牌走迷宫，每个结点给你下一块路牌。图中的箭头对应一次解引用，字段名 `{{fieldName}}` 或目标地址 `{{pointerTarget}}` 帮你判断这一跳来自哪个 C 字段。读图时逐段对应 C 代码，不要把所有结点看成同一个变量。

## STRUCT_ARRAY
`{{root}}` 是结构体数组，类型是 `{{typeName}}`。C 代码里访问元素和字段通常写成 `{{root}}[i].field`，当前元素表达式是 `{{cExpression}}`，下标路径是 `{{indexPath}}`。例子：`points[1].x = 7;` 先选数组第 1 个 `struct Point`，再访问它的 `x` 字段。类比一下，结构体数组像一排学生档案夹，每个档案夹里又有姓名、分数、next 等栏目。读图时先按下标找到第几个结构体，再看字段列表；这样能分清“第几个对象”和“对象里的哪个字段”。

## STRUCT_MATRIX
`{{root}}` 是结构体矩阵，类型是 `{{typeName}}`。C 代码里常写成 `{{root}}[row][column].field`，当前表达式是 `{{cExpression}}`，下标路径是 `{{indexPath}}`，位置在第 `{{row}}` 行第 `{{column}}` 列。例子：棋盘或网格上的 `cells[1][0].cost`，先定位一格结构体，再读写这一格的 `cost` 字段。类比一下，它像二维座位表，每个座位上不是一个数字，而是一张包含多个字段的小卡片。读图时先找行列，再展开字段；这能把二维数组访问和结构体字段访问分成两个清楚步骤。

## STRUCT_LIST
`{{root}}` 是结构体链表，类型是 `{{typeName}}`。C 代码里通常从头指针开始，沿着 `next` 这类字段一路走，例如 `head->next->value`；当前表达式是 `{{cExpression}}`。例子：`while (p != NULL) { p = p->next; }` 每循环一次，图上就从当前结点沿 next 箭头移动到下一个结点。类比一下，链表像一串接力卡片，每张卡片保存数据，也保存下一张卡片的位置。读图时把圆点或结点看成结构体对象，把箭头看成指针字段；遇到 NULL 就表示链条到头了。

## ARRAY_ELEMENT
元素 `{{cExpression}}` 来自根数组 `{{root}}`，下标路径是 `{{indexPath}}`，类型是 `{{typeName}}`。在 C 代码中，这个元素可以作为右值读取，也可以作为左值 `{{lvaluePath}}` 被赋值；如果本步有变化，可以把旧值 `{{oldValue}}` 和新值 `{{newValue}}` 对照起来。例子：`{{root}}{{indexPath}} = 7;` 就是在这一格写入新内容。类比一下，它是整排储物格中的一个格子，地址 `{{address}}` 表示这格在内存里的位置。

## MATRIX_ELEMENT
元素 `{{cExpression}}` 位于二维结构的第 `{{row}}` 行、第 `{{column}}` 列，下标路径是 `{{indexPath}}`，类型是 `{{typeName}}`。C 代码会用两个方括号先后定位，例如 `{{root}}{{indexPath}}`；第一个下标选行，第二个下标选列。如果当前步骤实际写的是字段，例如 `{{lvaluePath}}`，就表示先找到这一行这一列里的结构体，再进入具体字段。例子：`grid[1][0].x = 9;` 会落在第 `1` 行、第 `0` 列的 `x` 字段；旧值 `{{oldValue}}` 到新值 `{{newValue}}` 说明这一步改变了那个字段。类比一下，先找教室第几排，再找这一排第几个座位，最后看座位上卡片的哪一个栏目，顺序不能颠倒。

## STRUCT_FIELD
字段 `{{fieldName}}` 属于根结构 `{{root}}`，对应 C 表达式 `{{cExpression}}`，类型是 `{{typeName}}`。它可以作为左值路径 `{{lvaluePath}}` 被赋值，旧值 `{{oldValue}}` 到新值 `{{newValue}}` 的变化说明程序正在改结构体内部的这一栏。例子：`point.x = 7;` 只改 `x` 字段，不会影响同一个结构体里的 `y` 字段。类比一下，结构体字段像表格的一列，点号告诉你打开哪一栏。

## POINTER_ELEMENT
这个元素和指针有关：C 表达式 `{{cExpression}}` 的地址是 `{{address}}`，它指向 `{{pointerTarget}}`。读图时把当前格子看成保存地址的变量，真正的数据在箭头另一端；写 `*p` 或 `p->field` 才会沿着箭头访问目标。例子：`p = &x;` 改的是指针保存的地址，`*p = 3;` 改的是目标 `x`。类比一下，指针元素是一张路线卡，不是路线终点本身。

## POINTER_ARRAY_ELEMENT
元素 `{{cExpression}}` 是指针数组 `{{root}}` 中下标 `{{indexPath}}` 对应的格子，类型是 `{{typeName}}`。这个格子本身保存的是指针值，也就是目标地址 `{{pointerTarget}}`；C 代码访问 `{{root}}{{indexPath}}` 时先按下标找到这一格，再用 `*{{root}}{{indexPath}}` 或 `{{root}}{{indexPath}}->field` 继续访问目标。旧值 `{{oldValue}}` 到新值 `{{newValue}}` 表示这一格里的地址是否被改写。读图时把“数组下标”和“指针目标”分成两步看，避免把保存地址的格子和地址指向的数据混在一起。

## STRUCT_ARRAY_ELEMENT
元素 `{{cExpression}}` 是结构体数组 `{{root}}` 中下标 `{{indexPath}}` 对应的结构体对象，类型是 `{{typeName}}`。字段列表是 `{{fieldNames}}`，所以 C 代码通常会继续写成 `{{root}}{{indexPath}}.field` 来进入具体字段。旧值 `{{oldValue}}` 到新值 `{{newValue}}` 可以帮助你判断这个数组格子里的结构体内容是否变化。读图时先用数组下标定位第几个结构体，再用字段名判断正在读写哪一栏。

## STRUCT_MATRIX_ELEMENT
元素 `{{cExpression}}` 是结构体矩阵 `{{root}}` 中矩阵下标 `{{indexPath}}` 对应的结构体对象，位于第 `{{row}}` 行、第 `{{column}}` 列，类型是 `{{typeName}}`。字段列表是 `{{fieldNames}}`，C 代码常继续访问 `{{root}}{{indexPath}}.field`；如果当前步骤实际写的是字段，例如 `{{lvaluePath}}`，旧值 `{{oldValue}}` 到新值 `{{newValue}}` 说明这一步改变了那个字段。读图时先按二维数组的行列下标定位格子，再进入结构体字段；这样能把矩阵位置和字段访问拆成两个清楚步骤。

## POINTER_DEREFERENCE
这条箭头表示一次指针解引用：从 `{{address}}` 出发，沿着保存的目标地址 `{{pointerTarget}}` 找到下一块数据。C 代码中它常对应 `*p`、`p->field` 或链式访问中的一个 `->`；当前表达式是 `{{cExpression}}`，实际被读写的位置路径是 `{{lvaluePath}}`。例子：`*p = 7;` 会先沿箭头找到目标，再把目标位置的旧值 `{{oldValue}}` 改成新值 `{{newValue}}`；`head->next` 则会让图从 head 结点走向 next 指向的结点。类比一下，箭头就是“按纸条上的地址去找”的动作；如果目标是空地址，就说明不能继续解引用。

## STRUCT_POINTER_EDGE
这条箭头表示结构体指针的一次访问：从 `{{address}}` 沿着指针保存的目标地址 `{{pointerTarget}}` 找到结构体对象，再进入相关字段。C 代码里它常对应 `{{root}}->field`、`head->next` 或链式结构体指针访问；当前表达式是 `{{cExpression}}`，实际左值路径是 `{{lvaluePath}}`。读图时把“指针指向哪里”和“结构体字段是哪一个”分开确认，尤其要注意字段指针继续连到下一层时，每条箭头都代表一次解引用。

## STRUCT_LIST_NODE
结点 `{{elementLabel}}` 是链表 `{{root}}` 中的一个结构体对象，字段列表是 `{{fieldNames}}`。链表结点通常既保存数据字段，也保存 `next` 指针字段；`next` 指针决定图上下一条边会连到哪个结点。读图时先看这个结点的数据标签，再看它的 `next` 是否继续指向后继结点或结束在 NULL。

## STRUCT_LIST_EDGE
这条 `{{elementLabel}}` 边表示链表 `{{root}}` 的 `next` 指针关系：从当前结构体结点出发，沿着目标地址 `{{pointerTarget}}` 找到下一个结点。C 代码里它对应 `p = p->next` 或 `head->next` 这类访问。读图时每经过一条 `next` 边，就相当于沿链表指针前进一步。

## ELEMENT
这个可视化元素对应 C 代码里的 `{{cExpression}}`，它从根 `{{root}}` 派生出来，类型是 `{{typeName}}`，地址是 `{{address}}`。如果它有字段名、下标或指针目标，说明它不是孤立的一块文字，而是数组、结构体或指针关系中的一个部分。例子：它可能是 `a[0]`、`point.x` 或 `p`。类比一下，元素就是整张数据结构图中的一块拼图，理解它要同时看名字、位置和它与周围元素的连接。

## default
`{{root}}` 的类型是 `{{typeName}}`，当前可视化来自 C 代码表达式 `{{cExpression}}`。这个模板用于暂时没有专门分类的结构：它仍然会尽量显示根变量、地址 `{{address}}`、指针目标 `{{pointerTarget}}`、字段 `{{fieldName}}` 和下标 `{{indexPath}}`。例子：如果图上某个元素来自 `{{lvaluePath}}`，旧值 `{{oldValue}}` 到新值 `{{newValue}}` 可以帮助你看懂程序刚刚读写了哪里。类比一下，它像通用讲解牌，先把已知线索摆出来，再让你按 C 代码的访问顺序去对应图形。
