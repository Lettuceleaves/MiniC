## header
IR 可以理解成编译器给自己看的“备菜步骤”：C 代码在 AST 里还像一棵树，到了 IR 这里会被拆成先取值、再计算、再存回、再决定下一步去哪。这里看到的是第 ${lineNumber} 行，原始 IR 文本是 `${text}`，它对应 AST 中某个表达式、语句或控制结构被摊平后的一个小动作。这样拆开以后，后端生成汇编时就不用重新理解整句 C 代码，只要按这些顺序化步骤处理寄存器、内存和跳转。

## footer
把这些 IR 行连起来看，就能从 AST 的表达式节点、赋值节点、分支节点一路追到更接近机器执行的顺序。像 `x = add(x, 2);`、`return a + b;` 或 `for (int i = 0; i < 5; i = i + 1)` 这样的 C 片段，在 IR 里会显示出数据先在哪里产生、再传给谁，控制流又从哪个基本块走向哪个基本块。后端正是沿着这种更平直的表示去生成汇编：该算的值放进寄存器，该写回的值存进内存，该跳转的地方生成分支指令。

## call
call 表示函数调用；这行 IR 文本是 `${text}`，对应的 C 源码片段是 `${source}`。在 AST 里，`add(x, 2)` 或 `printf("value=%d\n", 42)` 通常只是一个函数调用表达式节点。IR 会把它单独拆出来，是因为调用函数不只是“算一个值”，还涉及把参数按顺序准备好、跳到目标函数执行、再把返回值接回来。后端生成汇编时会根据这一行安排调用约定：哪些参数放寄存器或栈上，调用哪一个函数符号，返回值之后要交给哪个临时结果继续使用。

## return
这行 IR 文本是 `${text}`，对应的 C 源码片段是 `${source}`。return 或 ret 来自 C 里的 `return` 语句，比如 `return a + b;` 在 AST 中会同时包含“计算 `a + b`”和“结束当前函数”两层意思。IR 通常会先把 `a + b` 拆成取值和加法步骤，再用 return 这一行明确表示函数要把哪个结果交出去。后端生成汇编时会把这个返回值放到调用约定要求的位置，然后生成函数收尾和返回到调用者的指令。

## branch
这行 IR 文本是 `${text}`，对应的 C 源码片段是 `${source}`。br 或 jump 来自 C 里的控制流写法，比如 `if (1 < 2)`、`for (int i = 0; i < 5; i = i + 1)`，以及循环中的 `break` 和 `continue`。AST 会把这些结构包成一棵带条件和语句块的树，但 IR 要把它们拆成“条件成立去哪里、不成立去哪里、循环结束去哪里”这样的基本块跳转。后端生成汇编时会把这些 IR 跳转翻译成条件分支或无条件跳转，让 `break` 能跳到循环外，让 `continue` 能跳到下一轮循环的更新或判断位置。

## compare
这行 IR 文本是 `${text}`，对应的 C 源码片段是 `${source}`。比较类 IR 来自 C 里的 `<`、`==`、`!=` 等条件表达式，比如 `if (1 < 2)` 里的 `1 < 2`，或 for 循环条件 `i < 5`。在 AST 里，比较常常嵌在 if 或 for 节点里面；IR 把它拆出来，是为了先得到一个明确的真假结果，再交给 branch 决定下一步去哪个基本块。后端生成汇编时通常会先生成比较指令或能产生条件码的运算，然后让后面的跳转指令读取这个结果。

## store
这行 IR 文本是 `${text}`，对应的 C 源码片段是 `${source}`。store 来自 C 里的赋值和写内存操作，比如 `x = add(x, 2);`，也包括数组写入 `values[2] = values[0] + values[1];`。AST 中赋值节点看起来是一整句，但 IR 要拆成先读右侧需要的值、完成函数调用或加法、再把结果写回左侧位置。后端生成汇编时会根据 store 知道哪个值必须落到变量槽、数组元素地址或其他内存位置，而不是只停留在临时寄存器里。

## load
这行 IR 文本是 `${text}`，对应的 C 源码片段是 `${source}`。load 来自 C 里读取变量或数组元素的地方，比如 `x = add(x, 2);` 需要先读出旧的 `x`，`values[0] + values[1]` 也需要先取出两个数组元素。AST 里这些读取可能只是变量名或下标表达式，但 IR 把它们单独列出来，是为了让“这一刻用到的值从哪里来”变得清楚。后端生成汇编时会把 load 变成从栈、全局区或计算出的数组地址取数的指令，然后把取到的值交给加法、比较或函数调用继续使用。

## default
这行 IR 文本是 `${text}`，对应的 C 源码片段是 `${source}`。这一行属于普通 IR 步骤，通常来自 AST 中不需要归到调用、返回、跳转、比较、读写内存这些类别的表达式或中间动作。比如 `a + b`、`i = i + 1` 中的加法，可能会先在 IR 里变成一个临时计算结果，再被 store、return 或 compare 使用。把这些小计算拆出来，就像做菜前把配料切好，后端生成汇编时可以逐步为每个临时值选择寄存器、发出算术指令，并把结果交给下一行 IR。
