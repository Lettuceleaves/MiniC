# MiniC 0.1.0 阶段总结

发布日期：2026-05-02

## 阶段定位

`0.1.0` 是 MiniC 的第一阶段稳定点。该阶段目标是先完成一个可观察、可测试、可运行的编译器闭环，再把语言能力扩展到一个基本可编程的 C 子集，并为下一阶段结构化编译观测和可视化能力建立基础。

## 已完成能力

- 项目工程：Java 21 Gradle 项目、Gradle Wrapper、基础 Git/文档/协作规则。
- 前端：源码位置、诊断、Token、Lexer、Parser、AST。
- 语义：函数/变量符号解析、作用域、类型检查、结构体布局、函数指针签名兼容。
- IR：基础 IR 模型、AST 到 IR lowering、局部变量、临时值、运行时检查插桩、控制流基本块。
- 后端：Windows x86_64 MASM 风格汇编生成，支持调用约定、栈帧、局部变量、参数、返回值和运行时 trap。
- 工具链：编译管线、CLI、可选汇编输出、MSVC `ml64/link` 工具链接入、compile-run 运行反馈。
- 语言控制流：`if/else`、`else if`、`while`、`for`、`break`、`continue`。
- 函数能力：函数声明/定义分离、递归、多参数、栈上传参、外部函数声明、动态链接 `printf`。
- 数据能力：字符串字面量、指针、取址/解引用、固定长度数组、数组到指针传参。
- 结构体：结构体声明、字段布局、`.` 和 `->` 字段访问。
- 函数指针：函数指针类型模型、声明解析、函数地址赋值、间接调用、函数指针作为参数传递。
- 类型系统：`bool`、有符号 `char`、`int`、`long`、`float`、`double`、`NULL`。
- 代码生成宽度：1 字节 `bool/char`、4 字节 `int/float`、8 字节 `long/double/pointer`。
- 浮点：SSE `float/double` 局部变量、参数、返回值、算术、比较和基础转换。

## 关键约定

- 首个目标平台是 Windows x86_64。
- 汇编文本采用 MASM 风格。
- MiniC 采用 `long = 8` 字节。
- `char` 是有符号 1 字节类型。
- `NULL` 是专门的空指针常量类型，可转换到指针。
- 当前 README 中记录的样例退出码仍是主要端到端行为基线。

## 当前边界

- 函数指针返回值当前明确不支持，会产出诊断。
- 类型系统是 MiniC 子集，不是完整 C 标准实现。
- 数组模型仍以固定长度数组为主，未覆盖动态分配、指针算术完整规则和复杂数组声明。
- 结构体支持字段访问和布局，但不支持结构体整体赋值。
- 浮点已经具备基本代码生成能力，但尚未覆盖完整 C 浮点环境、NaN 有序比较细节、可变参数 ABI 的浮点镜像寄存器规则等高级边界。
- 当前后端只支持 Windows x86_64；没有 Linux/macOS 后端。
- 没有 UI，可视化能力尚未开始。

## 验证方式

阶段内每个任务均以 Gradle 测试为基本验证。当前稳定验证命令：

```powershell
$env:JAVA_HOME='E:\projects\MiniC\.local\tools\jdk-21.0.10+7'
$env:PATH='E:\projects\MiniC\.local\tools\jdk-21.0.10+7\bin;' + $env:PATH
$env:GRADLE_USER_HOME='E:\projects\MiniC\.gradle-home'
.\gradlew.bat test
```

## 下一阶段讨论点

- 是否继续按原计划进入 Debugger 执行能力：`start`、`step`、`continue`、breakpoint。
- Debugger 技术路线：调用系统调试 API、解析外部调试器输出，还是先做解释执行式教学 debugger。
- 是否先补源码映射和 debug metadata，再做真实进程控制。
- 是否需要在进入 UI 前补齐更多语言边界和端到端样例。
- 下一阶段版本号建议：`0.2.0-SNAPSHOT`。
