# MiniC 0.2.0 阶段记录

发布日期：2026-05-03

## 阶段定位

`0.2.0` 是 MiniC 的结构化编译观测阶段。本阶段不扩展 C 语言能力，不引入 JavaFX UI，重点是把已有编译链路改造成可正向步进、可统一调度、可被 UI 门面稳定消费的数据结构。

## 四层结构

- 编译层：Lexer、Parser、Semantic、IR lowering、Windows x64 codegen 均提供可步进状态，并可构建与原一次性 API 等价的阶段输出。
- 兼容层：`minic.runtime.step` 提供统一 `StageStepper`、当前状态数据、当前阶段数据、全局数据、播放模式、控制能力和单步结果模型。
- 调度层：`minic.session` 提供编译观测会话，按阶段顺序串联 stepper，维护全局步骤计数、播放状态和阶段结果缓存。
- UI API 层：`minic.uiapi` 提供不依赖 JavaFX 的门面与不可变 DTO，供后续 UI 绑定。

## 已完成能力

- 测试基线收敛：保留综合行为和关键契约回归，减少后续结构化重构的脆弱断言。
- 结构化数据契约：定义编译阶段、单步结果、控制能力、当前状态、当前阶段数据和全局数据。
- 编译层可步进状态：
  - Lexer 每步产出一个 token 或词法 diagnostic。
  - Parser 每步完成一个顶层 AST 节点或错误恢复步骤。
  - Semantic 每步执行一个稳定类型语义动作。
  - IR lowering 每步推进一个关键 IR 结构动作。
  - Windows x64 codegen 每步产出一行汇编或结构行。
- 兼容层阶段 API：各阶段适配为统一 `StageStepper`，反向步进能力保留为 unsupported。
- 调度层：支持全局下一步、阶段切换、自动播放状态、两倍速播放状态、暂停、手动 tick、到末尾自动暂停。
- UI API：支持加载源码、开始会话、下一步、播放、两倍速播放、tick、暂停、previous/reversePlay 预留，以及当前状态、当前阶段数据和全局数据查询。
- UI DTO：覆盖当前状态、阶段数据、全局数据和控制结果，使用不可变集合并隔离内部 compiler/runtime/session 模型。

## 回归基线

`samples/**` 和 `src/test/java/minic/compiler/pipeline/**` 共同作为 `0.1.0` 功能健全基线：

- `samples/**` 记录已经验证过的端到端语言能力，预期结果以退出码、stdout 或代表性 diagnostic 为准。
- `MiniCompilerTest` 保留编译管线串联、代表性合法程序、词法/语义 diagnostic 短路、工具链产物和 compile-run 运行反馈。
- 结构化观测阶段优先测试新增的数据契约、步进状态和调度行为；除非发现真实回归，不为已经覆盖的旧语法补大量单语法细节测试。

已验证的代表样例：

```text

samples\arithmetic.mc           -> 退出码 7
samples\multi_function.mc       -> 退出码 12
samples\local_assignment.mc     -> 退出码 3
samples\divide_by_zero.mc       -> 退出码 102
samples\uninitialized_read.mc   -> 退出码 101
samples\nested_call.mc          -> 退出码 10
samples\stack_arguments.mc      -> 退出码 11
samples\declaration_call.mc     -> 退出码 12
samples\comparison.mc           -> 退出码 5
samples\if_else.mc              -> 退出码 7
samples\if_no_else.mc           -> 退出码 8
samples\nested_if.mc            -> 退出码 6
samples\else_if.mc              -> 退出码 2
samples\else_if_fallback.mc     -> 退出码 3
samples\while_zero.mc           -> 退出码 4
samples\while_count.mc          -> 退出码 5
samples\for_count.mc            -> 退出码 10
samples\for_omitted.mc          -> 退出码 4
samples\break_while.mc          -> 退出码 3
samples\continue_for.mc         -> 退出码 8
samples\printf.mc               -> 输出 value=42，退出码 42
```

其中 `102` 是除零运行时检查 trap，`101` 是未初始化局部变量读取 trap。
`samples\function_pointer_return_unsupported.mc` 用于覆盖当前限制：函数指针返回值暂不支持，会产出 parser diagnostic `暂不支持函数指针返回值`。

## 仍未实现项

- 未实现 JavaFX 或其他具体图形界面。
- 未实现反向步进、自动倒放或历史快照回退。
- 未实现断点、运行时 debugger、真实进程调试和源码级变量观察。
- 未实现工具链阶段 stepper；当前结构化观测覆盖到 codegen 汇编输出。
- IR lowering 的步进粒度当前是关键结构动作，不是函数内部每条 IR 指令的完全细粒度回放。
- 当前后端仍只支持 Windows x86_64。

## UI API 最小使用方式

```java
MiniCObservationApi api = new MiniCObservationApi();
api.loadSource("main.mc", "int main() { return 0; }");
api.startSession();

api.next();
UiCurrentStateDto state = api.currentState();
UiStageDataDto stageData = api.currentStageData();
UiGlobalDataDto globalData = api.globalData();

api.play();
api.tick();
api.playFast();
api.tick();
api.pause();
```

## 最终阶段总结

`0.2.0` 已完成结构化观测和 UI API 的阶段目标。MiniC 现在可以在不引入 JavaFX 的前提下，通过统一 UI 门面加载源码、开始观测会话、执行全局下一步、播放 tick、两倍速播放 tick、暂停，并查询当前状态、当前阶段数据和全局数据。

本阶段确认保持语言能力边界不变：不新增 C 语法，不改变 `0.1.0` 编译产物能力，不实现断点或运行时调试。后续工作可以在现有 `uiapi`、`session`、`runtime.step` 和编译层 step state 的边界上继续扩展，不需要让 UI 直接依赖 compiler 内部对象。
